# 双知识点多路径推演引擎（Dual-Knowledge Deduction Engine）

## Overview

推演失真 90% 的根源在于知识点没有结构化。本引擎不接受原始自然语言文本作为输入，而是强制将知识点解析为**结构化五元组**，在此基础上启用 **8 类推演算子** 并行生成多元演化路径，经过**聚类去重 → 分类排序 → 前景研判**，最终产出**可溯源、可验证、可审计**的企业级推演报告。

核心价值：
- **有限输入 → 发散因果推演**：从 2 个锚点知识生成多元分支，覆盖融合、冲突、传导、边界极限等视角
- **可追溯**：每一条推论都标注来源——来自知识 A/B 的哪一段逻辑 + 使用了哪种推演算子
- **企业可用**：结构化输出、可复用算子配置、支持迭代推演、可接入业务系统

## When to Use

- 你手里有两个（或少数）明确的知识点/能力/场景，想系统化探索它们的组合可能性
- 需要生成多条独立演化路径（而不仅是单一结论）用于战略决策参考
- 跨领域交叉创新：技术 A × 场景 B、方法论 X × 领域 Y
- 投资/立项前的可行性研判：系统化评估方案的前提、风险、前景
- 技术路线评估：两个技术方向的替代、互补、冲突分析
- 产品规划：核心能力 + 市场场景的演化前景推演

**不要用于：**
- 单知识点的普通问答或信息检索
- 已有明确唯一结论的简单线性问题
- 无输入约束的纯开放式畅想（应使用 brain-storming 类技能）
- 需要大量外部事实支撑的实证研究（应使用 research 类技能）

## Architecture（五层架构）

```
┌──────────────────────────────────────────────────────────────┐
│  第5层：输出标准化层（JSON + 自然语言 + 推演快照存档）        │
├──────────────────────────────────────────────────────────────┤

├──────────────────────────────────────────────────────────────┤
│  第1层：知识标准化底座（5元组结构化 + 冲突检测）               │
└──────────────────────────────────────────────────────────────┘
```

## Core Workflow（核心工作流）

### Step 1: 知识结构化（Knowledge Structuring）

对输入的 2 个（或少量）知识点，自动解析为**结构化五元组**：

```
知识ID｜核心实体｜内在机制｜适用边界｜已知约束
```

**示例：**

| 维度 | 知识A：大模型具备长文本摘要能力 | 知识B：企业存在大量零散历史文档 |
|------|------|------|
| 核心实体 | 大模型 | 企业历史文档 |
| 内在机制 | 语义压缩、关键信息抽取 | 静态信息载体 |
| 适用边界 | 结构化文本，无极强领域专业壁垒 | 版本杂乱、格式不统一 |
| 已知约束 | 超长上下文容易丢失细节 | 存在过期无效信息 |

**规则：**
- 缺失字段需提示人工补全，禁止跳过
- **知识冲突检测**：若 A 与 B 本身存在内在矛盾，推演前先告警，禁止直接混合推演
- 冲突类型标记：逻辑矛盾 / 数据矛盾 / 边界重叠矛盾

### Step 2: 算子并行推演（8 Operators）

给定已结构化的知识 A、知识 B，依次（或并行）执行全部 8 类推演算子，生成候选演化路径：

| # | 算子 | 定义 | 输出示例 |
|---|------|------|----------|
| 1 | **耦合融合** | A 能力叠加 B 场景 → A+B 形成新事物/新方案 | A摘要能力+B文档库=智能文档摘要系统 |
| 2 | **互补补位** | A 短板能否被 B 弥补；B 缺陷能否靠 A 解决 | A的上下文限制+B的文档结构=分段摘要方案 |
| 3 | **冲突制约** | A 内在规则与 B 约束发生冲突的场景 | A的通用摘要 vs B的领域术语导致精度下降 |
| 4 | **条件触发** | 满足什么外部条件后，A+B 组合才能生效 | 需要文档分类预处理→才能接入A的摘要 |
| 5 | **替代演化** | 用 A 改造 B 原有模式，或用 B 重构 A 落地方式 | A替代传统人工摘要→B文档自动归档+摘要 |
| 6 | **传导延伸** | A+B 形成中间产物，继续向外传导衍生二级、三级可能性 | 文档摘要→知识图谱→智能问答→决策辅助 |
| 7 | **边界极限** | 超出 A/B 适用边界后，组合失效、异化、产生负面结果 | 超长技术文档→摘要丢失关键细节→误导决策 |
| 8 | **规模放大** | 小规模成立，规模化落地后出现的新问题/新前景 | 1000份文档可行→100万份文档→成本/质量瓶颈 |

**企业配置**：算子可配置、可开关。不同行业启用不同算子权重，支持保存算子模板。

### Step 3: 路径聚类 + 去重 + 分类排序

1. **原始候选路径生成**：8 算子并行输出粗路径
2. **路径聚类去重**：基于核心逻辑相似度合并相近猜想
3. **路径三分类**：
   - ✅ **正向可行路径** — 逻辑自洽、具备现实可行性
   - ⚠️ **高风险路径** — 存在显著障碍但理论上可能
   - ❌ **天然不可行路径** — 逻辑矛盾或前提缺失
4. **路径排序**：按三维度打分
   - 实现难度（1-10）
   - 收益潜力（1-10）
   - 落地周期（短期/中期/长期）

**关键约束**：禁止只输出最优解，必须保留多条并行可能性；标注哪些是假设性推演、哪些具备现实案例支撑。

### Step 4: 前景评估研判（Prospect Assessment）

对每一条推演路径，输出标准化研判报告——**7 个必填维度**：

| 维度 | 内容 |
|------|------|
| ① 前置必要条件 | 缺少则无法实现的前提条件清单 |
| ② 短期前景 (0~12月) | 落地形态、预期收益、成本估算 |
| ③ 中期前景 (1~3年) | 行业格局变化、竞争态势 |
| ④ 长期前景 (3~10年) | 技术/模式生命周期、天花板 |
| ⑤ 核心风险清单 | 技术风险、政策风险、商业风险、实施风险 |
| ⑥ 最小验证方案 | 用什么最小实验去验证这条推演是否成立 |
| ⑦ 溯源链路 | 推论来自 A/B 哪一部分 + 使用何种算子 |

### Step 5: 标准化输出（Standardized Output）

#### 双格式输出：

**A. 结构化 JSON（机器可读）**

## Configuration（模式与参数）

### 双模式切换

| 参数 | 战略探索模式 | 可行性研判模式 |
|------|-------------|---------------|
| 发散系数 | 0.7~0.9（高发散） | 0.3~0.5（低发散） |
| 算子集 | 全部启用 | 侧重 1/2/4/7 |
| 幻觉管控 | 允许猜想，标注"假设性" | 严格限定 A/B 边界 |
| 路径保留 | 保留所有可能性 | 只保留可行+高风险 |
| 适用场景 | 研发战略、新方向探索 | 项目立项、投资评估 |

### 发散系数（Divergence Coefficient, 0~1）
- **0.0~0.3**：极度保守，仅做严谨推导，仅使用 A/B 显性信息
- **0.4~0.6**：平衡模式，允许合理延伸，要求标注推演等级
- **0.7~1.0**：高发散，允许创新猜想，用于战略探索

## Common Pitfalls

1. **跳过知识结构化直接推演** — 导致 90% 的推演失真。必须在 Step 1 完成结构化五元组解析，缺失字段人工补全。
2. **单一路径偏好** — 模型天然倾向于输出唯一最优解。必须强制保留多条路径，按三分类保留。
3. **无约束边界发散** — 超出 A/B 知识范围的无边界畅想。所有推论必须可溯源至 A 或 B，超范围自动标注警示。
4. **过度乐观前景** — 忽略边界极限算子（#7）的结论。必须确保边界极限和规模放大算子的输出被评估。
5. **混淆"可能性"与"必然性"** — 所有前景研判必须使用条件语言，标注假设前提。
6. **遗忘推演局限说明** — 任何推演都有前提，自动附加：外部重大变量不在本次推演范围。

## Verification Checklist

- [ ] 输入知识已解析为结构化五元组（entity / mechanism / boundary / constraint）
- [ ] 知识冲突检测已执行（A与B无内在矛盾，或已告警）
- [ ] 8类推演算子已全部执行（或按配置禁用部分）
- [ ] 路径已聚类去重，冗余度 < 30%
- [ ] 路径已三分类（可行 / 高风险 / 不可行）
- [ ] 每条路径包含完整的 7 维研判报告
- [ ] 每条路径包含溯源链路（来自A/B的哪一部分 + 使用算子）
- [ ] 输出包含推演假设与局限性声明
- [ ] 发散系数已标注（0~1）
- [ ] 推演快照已存档（用于回溯审计）
- [ ] 所有假设性推演已标注（非事实性结论）
- [ ] 双模式（探索/研判）参数已匹配场景
