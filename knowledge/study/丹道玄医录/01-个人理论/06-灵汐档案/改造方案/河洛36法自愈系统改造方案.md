### 第一层：SyndromeRouter 扩增（现有土层·fault_diagnosis.py）

扩增 `REPAIR_MAP` 从5种故障类型到覆盖全部36法，新增故障类型：

```python
class FaultType(Enum):
    SENSORY_DISTORTION = "sensory_distortion"    # 坎水
    DECISION_CONFLICT = "decision_conflict"       # 震乾
    NETWORK_FRAGMENTATION = "network_frag"        # 中宫
    SIGNAL_DISORDER = "signal_disorder"           # 离巽
    REASONING_DEVIATION = "reasoning_deviation"   # 推演
    # 新增（对应36法）
    STORAGE_CORRUPTION = "storage_corruption"     # 坎一·水 — 存储损坏
    NETWORK_LINK_FAILURE = "network_link_failure" # 坎一·水 — 链路漂移
    GIT_OBJECT_CORRUPTION = "git_object_corrupt"  # 震三·木 — 仓库内核
    GIT_PUSH_PULL_FAILURE = "git_push_pull_fail"  # 巽四·木 — 推拉协作
    CI_PIPELINE_FAILURE = "ci_pipeline_failure"   # 离九·火 — CI/CD

```

## 五、当前系统与36法对比的物化证据

当前系统 `fault_diagnosis.py` 仅处理5种故障类型，5个修复程序字符串：
```
"程序①交叉校验"
"程序②链路修复+通路平衡"
"程序③权限锁唤醒管控"
"程序④全网节律同步"
"程序⑤五行制衡调优"
```

而36法要求覆盖：
```
坎宫6法 → 存储/数据/网络
震巽12法 → Git仓库+推拉
离宫6法 → CI/CD
乾兑6法 → 安全/权限
坤艮6法 → 容灾/熔断
中宫 → 贯穿约束
```

**差距量化**：当前系统实现 ~15% 的36法覆盖，需新增85%的修复能力。
