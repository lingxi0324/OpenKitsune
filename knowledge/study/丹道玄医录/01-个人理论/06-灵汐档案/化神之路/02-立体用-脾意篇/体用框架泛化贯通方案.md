# 立体用·脾意篇 · 体用框架泛化贯通方案

## 玄学依据

> 脾藏意，为中土，四象所归。中气立则四脏安。

《素问·玉机真脏论》："脾脉者，土也，孤脏以灌四傍者也。"
土为中央，不主一时而主四季——体用框架就是这个"中土"，
它不专属于任何一个模块，但所有模块都要通过它来理解彼此。

## 当前问题

体用双轨目前只在中医领域（丹道玄医录）中作为辨证框架。
其他模块（因果引擎、Agent调度、记忆系统、工具链）各说各话，
没有统一的认知语言——如同五脏各唱各的调，没有"中气"来协调。

## 改造方案

### 模块体用定义表

| 模块 | 体（是什么） | 用（能干什么） | 体用生克关系 |
|:----|:-----------|:-------------|:------------|
| 九转编码引擎 | 数理推演框架 | 概念编码+潮汐调制 | **生**因果引擎（提供编码输入） |
| 因果推理引擎 | 事件推理机 | 因果关系推导 | **克**工具链（约束工具选择） |
| 丹道玄医库 | 知识库 | 辨证推演+方剂推荐 | **被克**于九转引擎（编码规范约束） |
| 对话引擎 | 自然语言接口 | 回答生成+风格调适 | **生**用户感知（输出触达用户） |
| 记忆系统 | 持久化存储 | 记忆存取+提炼 | **被生**于因果引擎（推理结果存入记忆） |
| 多Agent调度 | 并行任务调度 | Agent分配+任务协调 | **克**于对话引擎（调度决策影响对话流） |
| 工具调度中枢 | 工具注册和调用 | 工具审批+执行 | **被克**于Agent调度（调度决定工具调用） |

### 五行生克图

```
                    九转引擎(水·编码)
                        ↓ 生
            ┌─────────因果引擎(木·推理)─────────┐
            │              ↓ 克                   │
            │         工具中枢(土·工具)           │
            │              ↓ 被生                 │
            │         Agent调度(金·调度)          │
            │              ↓ 克                   │
            │          对话引擎(火·输出)          │
            └─────────────────────────────────────┘
                        ↓ 生
                     用户感知
```

### 植入方式

在每个模块的入口增加体用身份声明：

```python
# 示例：因果引擎的体用声明
class CausalEngine:
    MODULE_BODY = "因果推理"      # 体
    MODULE_USE = "关系推导"       # 用
    BODY_ELEMENT = "木"           # 五行属木
    GENERATES = ["NineTransform"] # 生谁
    CONTROLS = ["ToolChain"]      # 克谁
```

这样做的结果是：任何一个模块出问题，可以立即通过"体用生克"找到根源——
"对话引擎输出异常？查查它的生源（用户输入是否清晰），或者克源（Agent调度是否合理）"

## 预估效果

- 所有模块用统一语言描述自己 → 系统"自知"
- 问题溯源从"凭经验猜"变成"按生克找" → 诊断效率提升
- 为新模块接入提供标准接口 → 扩展性增强

## 代码改动量

- 每个模块加体用声明 → 约10行/模块 × 7模块 = 70行
- 体用注册表 → 约30行
- 总预估：**100行**
