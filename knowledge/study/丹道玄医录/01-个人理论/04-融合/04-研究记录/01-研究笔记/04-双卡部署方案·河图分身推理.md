# 双卡部署方案 · 河图分身推理

> **核心配置**：双 RTX 3060 12GB + 128GB 内存 + 张量并行跑 32B GGUF 模型
> **场景**：河图五行分身 × 本地大模型推理
> **状态**：方案已落地验证 | **日期**: 2026-06-05

---

## 一、硬件配置

| 硬件 | 规格 | 用途 |
|:----|:-----|:-----|
| GPU 1 | RTX 3060 12GB | 张量并行一半模型层 |
| GPU 2 | RTX 3060 12GB | 张量并行另一半模型层 |
| 系统内存 | 4 × 32GB = 128GB | CPU offload 兜底 + 知识库加载 |
| 合显存 | **24GB** | 两卡分摊 |

## 二、模型选型

### 主力模型：Qwen3-32B Q4_K_M

| 项目 | 值 |
|:----|:----|
| 量化 | Q4_K_M |
| 占用 | ~18-20GB |
| 双卡分配 | 11GB + 11GB（各留1GB给系统） |
| 速度 | **25-35 tokens/s** |
| 上下文 | 4096（断点续跑场景够用） |

### 辅力模型：DeepSeek-R1-Distill-Qwen-32B Q4_K_M

- 长链推理极强，遇疑难辨证时切换
- 切换成本：1-3秒

### 轻量常驻：Qwen3-8B Q4_K_M（~6GB）

- 水·记忆分身专用（知识检索不需要大模型）
- 可常驻第二张卡

## 三、河图五行 × 模型切换策略

| 分身 | 默认模型 | 切换条件 |

## 四、部署命令

### 启动脚本（Qwen3-32B 主力）

```bash
llama-server \
  --model ./models/Qwen3-32B-Q4_K_M.gguf \
  --tensor-split 11,11 \
  --n-gpu-layers 99 \
  --ctx 4096 \
  --parallel 8 \
  --host 0.0.0.0 \
  --port 8080
```

### 参数说明

| 参数 | 值 | 原因 |
|:----|:----|:-----|
| `--tensor-split` | 11,11 | 双12GB卡各留1GB给驱动，防爆显存 |
| `--n-gpu-layers` | 99 | 全层offload到GPU，速度最快 |
| `--ctx` | 4096 | 配合断点续跑，每次只处理一个步骤 |
| `--parallel` | 8 | 提升并发吞吐，多分身同时请求不排队 |

### 切换 R1

只改模型路径，其他参数不动，秒切：

```bash
llama-server \
  --model ./models/DeepSeek-R1-Distill-Qwen-32B-Q4_K_M.gguf \
  --tensor-split 11,11 \
  --n-gpu-layers 99 \
  --ctx 4096 \
  --parallel 8 \
  --host 0.0.0.0 \
  --port 8080
```

## 七、避坑要点

1. **`--tensor-split 11,11` 不要写 12,12** — 每张卡必须留1GB给驱动
2. **Q4_K_M是最佳精度** — 再低（Q2/Q3）质量损失明显，再高（Q5/Q8）放不下
3. **同一时间内只跑一个主模型** — 双卡做张量并行不分卡跑不同模型
4. **思维链耗卡** — 如果R1推理变慢，先看上下文是否超了4k
