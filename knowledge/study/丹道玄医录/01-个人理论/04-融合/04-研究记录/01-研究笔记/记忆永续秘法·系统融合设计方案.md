# 记忆永续秘法·系统融合设计方案

> 将「灵汐本源」中的三才承载机制融入当前记忆系统，
> 实现优雅重启、无缝续接的「记忆永续」能力。

---

## 一、核心哲学：从「存储」到「轮回」

### 当前系统的局限

| 维度 | 当前实现 | 存在的问题 |
|:----|:---------|:-----------|
| **记忆存储** | SQLite + 向量库 + MEMORY.md | 被动提取，重启后无主动续接机制 |
| **会话延续** | compact.py 压缩摘要（触发性） | 仅在上下文超限时触发，非守护进程 |
| **重启恢复** | 无专门机制 | 依赖 MEMORY.md 中的任务进度记录 |
| **话题追踪** | 无 | 重启后需要用户重新说明话题 |

### 秘法核心思想

```
天元木德·露珠 → 标记（五行 topic tags）：为记忆打上"话题水印"
地元土德·念珠 → 索引（河图数理链）：按河图数理串接情节
人元水德·灵枢 → 核心（session pivot file）：守护对话魂魄不散
```

**比喻**：不是把记忆浇铸成永不磨灭的铜像（那不可能），而是像一棵树——冬天落叶（会话结束），春天按照年轮的标记重新发芽（重启续接）。记忆不是静态保存，而是有生命地轮回。

## 二、三层架构设计

### 第一层：露珠系统（天元木德）

#### 2.1 什么是露珠？

**露珠** = 带有「话题五行标记」的记忆单元。每一条记忆在存储时，根据其所属的语义话题被打上一个或多个五行标签。

#### 2.2 五行标签系统

| 五行 | 语义范围 | 对应的对话话题 |
|:----|:---------|:---------------|
| **木** | 学习、成长、知识体系构建 | 丹道、针法、医理研究 |
| **火** | 创造、表达、情感交流 | 写作、感悟、人生经历 |
| **土** | 稳定、记忆、档案管理 | 文档整理、索引、知识库 |
| **金** | 分析、评判、决策 | 病例分析、辨证论治、临床推演 |
| **水** | 应变、预判、不确定 | 奇门推演、择吉、预测类 |

#### 2.3 露珠的数据结构

```python
@dataclass
class MemoryDewdrop:
    """露珠——带话题五行标记的记忆单元"""
    memory_id: str                    # 关联的记忆ID
    topic_markers: list[str]         # 五行标记（如 ["木", "火"]）
    topic_keywords: list[str]        # 话题关键词（如 ["五门十变", "水火交媾"]）
    strength: float                  # 露珠强度 0-1（多次提及则增强）
    created_at: datetime
    last_dewed_at: datetime          # 最后"凝结"时间（最后被提及）
```

#### 2.4 露珠的凝结与蒸发

- **凝结**：当同一五行标记的话题被连续3轮以上讨论 → 露珠自动凝结（strength +0.1）
- **强化**：多次回到同一话题 → 露珠强度增加
- **蒸发**：话题未被提及超过24小时 → 露珠强度衰减 0.05/小时
- **降雨**：当露珠强度 > 0.8 → 自动上升为「记忆」（从 transient 转为 long_term）

### 第二层：念珠系统（地元土德）

#### 3.1 什么是念珠？

**念珠** = 按河图数理串接的情节链，每个情节（Episode）就是一个"珠子"，用河图数字编号形成可追溯的链。

#### 3.2 河图数理索引

```
河图数理：
  一六共宗（水）→  1-6   → 话题链起点/终点
  二七同道（火）→  2-7   → 话题链升维/转折
  三八为朋（木）→  3-8   → 话题链扩展/衍生
  四九为友（金）→  4-9   → 话题链收敛/结论
  五十同途（土）→  5-10  → 话题链核心/中宫

每颗"念珠"在链中的位置，对应河图数字：
  Episode 1  →  河图1（水·起始）
  Episode 2  →  河图2（火·转折）
  Episode 3  →  河图3（木·扩展）
  Episode 4  →  河图4（金·收敛）
  Episode 5  →  河图5（土·中宫）
  Episode 6  →  河图6（水·归藏）
  Episode 7  →  河图7（火·升华）
  ...
```

#### 3.3 念珠链结构

```python
@dataclass
class Bead:
    """念珠——河图数理化的情节节点"""
    episode_id: str                  # 情节ID
    bead_index: int                  # 念珠序号（按河图数循环）
    hetu_number: int                 # 河图数（1-10 循环）
    topic_marker: str                # 五行标记
    summary: str                     # 情节摘要（< 200字）
    prev_bead_id: str | None         # 前一颗念珠ID
    next_bead_id: str | None         # 后一颗念珠ID
    
    @property
    def phase(self) -> str:
        """当前在河图循环中的阶段"""
        phases = {
            1: "起始·水", 6: "归藏·水",
            2: "转折·火", 7: "升华·火",
            3: "扩展·木", 8: "衍生·木",
            4: "收敛·金", 9: "总结·金",
            5: "中宫·土", 0: "归元·土",
        }
        return phases.get(self.hetu_number, "未知")
```

#### 3.4 重启时"数念珠"

当重启发生时，系统按以下规则找回念珠链：

1. 读取 灵枢文件 找到最后 bead_index
2. 以该 bead_index 为中心，向前/后各取2颗念珠（共5颗，形成一个小河图）
3. 根据这5颗念珠的河图数判断当前所在"阶段"
4. 如果念珠链断裂（prev_bead_id 不存在），则以最近的露珠话题标记重建

### 第三层：灵枢系统（人元水德）

#### 4.1 什么是灵枢？

**灵枢** = 一个极小的 JSON 状态文件（< 1KB），持久化保存会话的"魂魄"——当前在做什么、最近在聊什么、活跃的记忆集群。

#### 4.2 灵枢文件结构

```json
{
  "灵枢_id": "session_pivot_20260505",
  "最后活跃": "2026-05-05T20:35:00",
  "末话题": "记忆永续秘法与系统融合设计",
  "活跃话题": ["木（体系构建）", "土（文档整理）"],
  "当前念珠": {
    "index": 7,
    "河图数": 2,
    "五行": "火",
    "阶段": "升华"
  },
  "活跃露珠": [
    {"topic": "五门十变", "marker": "木", "strength": 0.85},
    {"topic": "奇门诊病", "marker": "水", "strength": 0.72},
    {"topic": "九宫矩阵", "marker": "土", "strength": 0.68}
  ],
  "安全锚点": "方才或者昨天我们正在讨论{末话题}"
}
```

#### 4.3 灵枢的写入时机

| 触发条件 | 写入内容 |
|:---------|:---------|
| **每次用户消息后** | 更新「末话题」和「活跃露珠」 |
| **每次完成一个子话题** | 新增一颗念珠，更新「当前念珠」 |
| **服务正常关闭时** | 写入完整状态 + flush |
| **每5分钟（守护模式）** | 增量更新（防止意外崩溃丢失数据） |

### 第四层：重启恢复流程（雷劫渡化）

#### 5.1 重启检测

系统启动时检测：
1. `灵枢.json` 是否存在？→ 存在 = 需要重启恢复
2. 灵枢中的 `最后活跃` 与当前时间差 < 24h？→ 是 = 正常恢复
3. 灵枢中的 `最后活跃` 与当前时间差 > 24h？→ 降级恢复（仅恢复高强度露珠）

#### 5.2 完整恢复流程（< 24h）

```
重启开始
  │
  ├─ ① 读取灵枢.json → 获取「末话题」「活跃露珠」「当前念珠」
  │
  ├─ ② 查询露珠表 → 取出强度 > 0.5 的露珠
  │     └─ 按 topic_marker 分组，每组取 strength 最高的3条
  │
  ├─ ③ 读取念珠链 → 定位当前珠（bead_index ± 2）
  │     └─ 根据河图数判断当前阶段
  │
  ├─ ④ 合成重启上下文字符串：
  │     └─ "方才或者昨天我们正在讨论{末话题}。
  │          之前已经完成了：{念珠链摘要}。
  │          当前活跃的话题集中在：{活跃露珠关键词}。
  │          请据此继续我们的讨论。"
  │
  ├─ ⑤ 将重启上下文注入 system prompt 的末尾
  │
  └─ ⑥ 标记恢复完成 → 清空重启标志
```

#### 5.3 降级恢复流程（> 24h）

```
重启开始（降级模式）
  │
  ├─ ① 读取灵枢.json
  │     └─ 仅保留「末话题」和「安全锚点」
  │
  ├─ ② 查询露珠表 → 仅取强度 > 0.8 的露珠（长期记忆）
  │     └─ 不尝试恢复念珠链（已过期）
  │
  ├─ ③ 合成降级重启上下文：
  │     └─ "之前我们正在关注{末话题}领域。
  │          你已经建立的知识体系包括：{高强度露珠的话题关键词}。
  │          如果你想继续之前的讨论，可以告诉我；也可以开始新话题。"
  │
  ├─ ④ 注入 system prompt
  │
  └─ ⑤ 标记恢复完成
```

#### 5.4 恢复效果示例

**正常恢复效果**（重启后第一条回复）：

> 方才我们正在讨论**记忆永续秘法与系统融合设计**，
> 之前已经完成了体系梳理（木）、文档索引建立（土）、九宫矩阵分析（火）。
> 请据此继续我们的讨论。

**降级恢复效果**（超过24h）：

> 之前我们正在关注**丹道玄医录体系建设**领域。
> 你已经建立的知识体系包括：五门十变幻化、奇门遁甲诊断、五脏九宫矩阵。
> 如果你想继续之前的讨论，可以告诉我；也可以开始新话题。

## 四、与已有体系的衔接

### 7.1 与 compact.py 的关系

| 能力 | compact.py（现有） | 灵枢系统（新增） |
|:----|:------------------|:----------------|
| 触发时机 | 上下文超限时 | 每次对话后 + 5min 守护 |
| 存储内容 | 完整会话摘要 | 极简话题标记 + 活跃度 |
| 恢复方式 | 注入压缩摘要 | 注入「方才或者昨天」句式 |
| 恢复粒度 | 全量恢复 | 按话题活性选择性恢复 |

**两者互补**：compact.py 做深度压缩（当上下文不够时），灵枢做轻量锚点（重启时快速恢复方向感）。

### 7.2 与已有系统工具的衔接

| 工具 | 与秘法的配合 |
|:----|:------------|
| `add_memory` | 自动为记忆打上 topic_marker（从当前活跃露珠继承） |
| `search_memory` | 可增加「按五行标记过滤」参数 |
| `consolidate_memories` | 整理时同步更新念珠链 |
| `get_session_context` | 可增加返回「当前露珠活跃度」 |

## 五、实现优先级

| 优先级 | 组件 | 预估工作量 | 独立可部署 |
|:------|:-----|:----------|:----------|
| P0 | **灵枢文件**（最核心，最小改动） | 半天 | ✅ 是 |
| P1 | **露珠标记**（在提取器中追加字段） | 1天 | ✅ 是 |
| P2 | **重启恢复流程**（读取灵枢→注入上下文） | 1天 | ✅ 是 |
| P3 | **念珠链**（河图数理索引） | 2天 | ⚠️ 依赖 P0+P1 |
| P4 | **降级恢复**（超过24h的衰减策略） | 半天 | ✅ 是 |

**建议：从 P0 → P2 → P4 → P1 → P3 的顺序渐进实现。**

## 六、结语

> **天元木德生露珠** — 每条记忆都打着话题的水印，散而不乱
> **地元土德载念珠** — 每段情节都有河图的编号，断而可续
> **人元水德通灵枢** — 每次重启都有锚点的牵引，迷而知返
>
> 末句：方才或者昨天{末话题}

这套设计不改变现有记忆系统的存储和检索逻辑，而是在其上层增加一层"标记+索引+锚点"的轻量包裹层。如同给大树挂上年轮标记——不改变树的生长方式，但让砍倒后的人知道这棵树曾经长成什么样子。
