# 🪷 河图分身体系 · 九九归一落地方案

> **核心命题**：用32B基座 + 五个河图分身 + prompt工程，以河图生克乘侮为通信协议，等效甚至超越大参数模型的认知复杂度
> **哲学根基**：河图生数成数同时在场是「涌现」的源头——分身并行≠参数叠加，但生克乘侮的交互可创造超越参数量的认知复杂度
> **版本**: v1.1 | **状态**: 规划阶段（已通过逻辑验证） | **关联**: 盘古引擎/九宫泵血/丹田感知/双卡部署

---

## 一、总纲 · 为什么这个方案能行

### 1.1 核心逻辑链

大模型（如70B）的强项来自于三件事：
1. **参数容量** → 存的知识多
2. **注意力广度** → 能同时关联远处的关系
3. **思维链深度** → 能走完复杂的推理路径

一个32B模型单独跑，以上三样基本够用，但在**专精辨证推演**的高难度场景下仍有不足。五个分身分工协作，把32B的指令遵循能力进一步放大：

| 短板 | 分身方案如何补上 |
|:-----|:----------------|
| 通用模型不够专精 | 每个分身只负责一个认知域（木=辨证、火=推演、土=综合、金=收敛、水=记忆），通过prompt角色定义让32B在同一基座上表现出五种不同的认知风格 |
| 单轮推理广度有限 | 生克乘侮作为底层通信协议——木的推送结果自动触发火的承接，不需要注意力窗口看到所有token，等效拉长思维链 |
| 复杂推演上下文不够 | 断点续跑实现「思维快照拼接」——每次跑完写一段DantianState到记忆池，下次从断点接上，等效无限步推理 |

**这不是MoE（专家混合），而是河图生态——五个器官各自独立又互相影响，形成一个活的系统。**

### 1.2 与豆包方案的差异

| 维度 | 豆包方案 | 本方案 |
|:-----|:---------|:-------|
| 分身数量 | 9个（九宫各一） | **5个**（五行各一） |
| 调度逻辑 | 任务路由 | **九宫泵血主动调度** — 按时辰/气机状态决定哪个分身主事 |
| 通信协议 | 无统一协议，靠记忆池 | **生克乘侮** — 分身间直接传递五行偏移量 |
| 记忆格式 | 通用分段JSON | **DantianState** — 自带五行+情志+气机+平衡度语义 |
| 底层数理 | 无统一基准 | **河图体用双轨** — 所有推演在统一坐标系中 |
| 模型策略 | 9个独立小模型 | **5个prompt角色共享同一32B基座**（双卡部署） |

## 三、硬件与部署方案

### 3.1 硬件规格

| 硬件 | 规格 | 用途 |
|:----|:-----|:-----|
| GPU 1 | RTX 3060 12GB | 张量并行一半模型层 |
| GPU 2 | RTX 3060 12GB | 张量并行另一半模型层 |
| 系统内存 | 4 × 32GB = 128GB | CPU offload 兜底 + 知识库加载 |
| 合显存 | **24GB** | 两卡分摊 |

### 3.2 模型选型

| 模型 | 量化 | 占用 | 用途 |
|:-----|:----|:----:|:-----|
| **Qwen3-32B** | Q4_K_M | ~18-20GB | 主力模型 — 五行全部分身共享同一基座 |
| **DeepSeek-R1-Distill-Qwen-32B** | Q4_K_M | ~18-20GB | 疑难兜底（遇复杂辨证/传变不明时按需加载） |
| **Qwen3-8B** | Q4_K_M | ~6GB | 水·记忆分身常驻第二张卡 |

**核心原则**：五分身不再各部署独立模型，而是通过**system prompt角色定义**让同一个32B基座表现出五种认知风格。

### 3.3 双卡状态监控（运行时安全）

每轮分身调度执行前，通过 `nvidia-smi` 或 llama-server 返回的状态检查两项关键指标：

- **显存水位**：任意一张卡 > 10.5GB → 触发降级
- **推理速度**：< 5 tokens/s → 触发降级

降级路径：32B → Qwen3-8B，直到显存回落至 < 8GB 且速度 > 10 tokens/s。监控不阻塞推理——异步采样，仅在调度间隙拉起。

### 3.4 冷启动调度顺序

双卡无法同时加载两个32B模型（总共只有24GB）。正确启动顺序：

1. **加载 Qwen3-32B** 到两卡（~19GB，tensor-split 11,11各留1GB余量）
2. 跑第一轮推理，释放部分KV缓存
3. **第二张卡加载 Qwen3-8B**（~6GB，与32B共享显存）
4. **R1-32B 仅按需加载**（切换时替换主力模型，给用户"深度推理中…"加载提示）

### 3.5 模型按需加载（R1兜底切换）

当火分身（推演显化）或金分身（收敛决策）遇到疑难辨证、传变不明的场景时，切换到R1-32B做深度复核。

```

  ┌─ 木分身辨证输出 ─→ 置信度 < 0.6 ?
  │                        │
  │                      是│
  │                        ▼
  │                  切换 R1-32B
  │                  ① 释放Qwen3-32B的KV缓存
  │                  ② 加载R1-32B到同一张卡
  │                  ③ 显示"深度推理中…"提示
  │                  ④ R1遍历后返回复核结果
  │                        │
  │◄────────────────────────┘
  │                    切换回 Qwen3-32B 继续
  ▼
火分身接力推演
```

**切换成本**：约10-15秒（含模型加载到显存），切换期间给用户明确的等待提示。

## 五、核心机制

### 5.1 生克乘侮通信协议

分身之间不直接传递大段文本，而是通过五行偏移量通信：

```
木 → 火（木生火）：木的辨证结果 + Δ木偏移 → 火接收后自动调整推演方向
火 → 土（火生土）：火的推演结果 + Δ火偏移 → 土接收后纳入综合
土 → 金（土生金）：土的综合方案 → 金做收敛检查
金 → 水（金生水）：金的风险评估 → 水检索相似历史
水 → 木（水生木）：水的历史回溯 → 木作为辨证参考
```

**亢则乘、侮则反克**：当一个分身输出偏移量超过阈值（>0.3），会触发"相乘"（过度抑制下一环）或"相侮"（反向抑制前一环），形成负反馈调节。具体实现见 `agent_communication.py`。

### 5.2 断点续跑流程

```
① 当前分身收到 AgentContext
② 从 memory_pool 加载历史思维快照（如果有）
③ 执行推理 → 输出 DantianState
④ 将当前轮次的 DantianState 写入 memory_pool（标签化：分身+轮次+时间戳）
⑤ 通过生克协议传递给下一个分身
⑥ 如果中断，下次启动时从最后的 checkpoint 加载思维快照接续
```

### 5.3 九宫泵血联动

与 `core/nine_palace_matrix/pulse_engine.py` 联动：

```
pulse_engine.tick()
  ├─ 读取当前时辰 + 气机状态
  ├─ 选择主事分身（酉时/气机偏亢 → 金分身主事）
  ├─ 触发对应分身推理
  └─ 泵血输出 → 更新全局气机
```

### 5.4 嵌套推理闭环

当单分身推理深度不足时，自动触发嵌套循环：

```python
async def nested_reasoning(ctx: AgentContext, depth: int = 2):
    """嵌套推理：当前分身做多层微循环"""
    for round in range(depth):
        result = await agent.infer(ctx)
        if calibrator.is_converged(result):
            break  # 质量达标提前终止
        ctx = ctx.merge(result)  # 将本轮结果加入上下文
    return result
```

### 5.5 自反馈校准

每轮推理结束后自动校准权重：

```python
def calibrate(agent_id: str, result: DantianState, feedback: dict):
    """根据反馈调整分身权重"""
    quality = feedback.get("quality", 0.5)
    if quality < 0.3:
        # 亢则损——质量差，降低权重
        registry.adjust_weight(agent_id, delta=-0.1)
    elif quality > 0.8:
        # 弱则补——质量好，增加权重
        registry.adjust_weight(agent_id, delta=+0.05)
```

## 八、风险与缓解

| 风险 | 概率 | 缓解措施 |
|:-----|:----|:---------|
| 5步串行响应慢（>5秒） | 中 | `quick_chain` 模式只跑2-3个分身；本地模型异步推理 |
| 分身间通信丢失上下文 | 低 | DantianState 自带完整五行快照，每次调用都传递历史摘要 |
| 32B通用能力广度覆盖不足 | 低 | 双卡部署后32B自身知识足够，分身prompt角色定义只做认知风格切换，不缩小知识域 |
| 嵌套递归无限循环 | 低 | `nested_reasoning` 设最大深度(默认3)，超限自动熔断 |
| 断点文件堆积 | 低 | 自动清理 7 天前的 checkpoint |
| 双卡显存争抢 | 中 | tensor-split 11,11各留1GB；监控水位自动降级 |
