## 四、七步归元法（落地版详解）

### ① 盘瓠观天 ── 感知层（坎水 1→6）

**代码位置：** `sixiang_guiyuan.py` → `_step_panhu_guantian()`

**感知维度：**
- 工具调用失败率异常升高
- 同类操作重复出现（反复裂隙标记）
- 系统性能变化（响应变慢、内存升高）
- 任务完成质量下降

**Org 集成（v3.0 新增）：** `org_data_bridge.py`

| 策略 | 扫描范围 | 裂隙类型 |
|:---|:---|:---|
| `scan_node_failures()` | 各组织节点连续失败次数 | `task_failure` |
| `scan_stuck_nodes()` | 各组织节点运行时长 | `node_stuck` |
| `scan_commands()` | 待处理和超时命令 | `command_timeout` |
| `scan_heartbeats()` | 心跳健康状态 | `heartbeat_dead` |
| `scan_pending_events()` | 堆积而未处理的事件 | `event_backlog` |

**后台轮询（v3.0 新增）：** `org_auto_poller.py`

```
OrgRuntime → OrgDataBridge(60s/次) → FissureCandidate → SixiangGuiyuanEngine
```

每60秒自动扫描，去重（10分钟内同裂隙不重复触发）、冷却（两次迭代至少间隔120秒）、熔断保护。

### ② 灵汐辨证 ── 诊断层（离火 2→7）

**代码位置：** `sixiang_guiyuan.py` → `_step_lingxi_bianzheng()`

**四证辨证矩阵（20组交叉定位）：**

| 气证（动力不足） | 血证（通道瘀堵） | 水证（收敛亏虚） | 火证（发散滞涩） |
|:---|:---|:---|:---|
| 配置层 | 配置未生效 | 配置路由冲突 | 配置未持久化 | 配置同步频率不足 |
| 代码层 | 方法未实现 | 模块间不连通 | 数据未落盘 | 代码执行频次异常 |
| 逻辑层 | 流程断点 | 链路不通 | 缺少归档机制 | 触发频率失衡 |
| 知识层 | 知识缺失 | 知识库不连通 | 经验未固化 | 学习周期过长 |
| 体验层 | 反馈无响应 | 信息传递阻断 | 上下文丢失 | 交互频率过高 |

**输出：** 证型 + 层次 + 根因 + 置信度 + `type_scores` + `layer_scores` + `hetu_position`

### ③ 绿汐炼石 ── 执行层（震木 3→8）

**代码位置：** `sixiang_guiyuan.py` → `_step_lvxi_lianshi()`

**三路径决策：**

```
fitxure_type == 已有 | layer_change == 小范围
    → 修复路径（生成代码/配置补丁 + 回滚脚本）
    
fitxure_type == 新能力 | pattern == 新需求

step_metrics 质量连续下降 | user_force_self_refer
    → 自指向路径（生成七步自身升级方案）
```

**输出：** `path_type` + `patches[]` + `self_refer_plan`（自指向时）+ `impact_analysis`

### ④ 白羽验石 ── 验证层（兑金 4→9）

**代码位置：** `sixiang_guiyuan.py` → `_step_baiyu_yanshi()`

**四维校验：**
1. **语法正确性** — 补丁代码无语法错误
2. **安全性** — 无越权写入/网络调用等敏感操作
3. **回滚可行性** — 回滚脚本可执行且能恢复完整状态
4. **影响范围** — 标注受影响的模块、接口、配置项

**决策：** ✅ 常规通过 / ⚠️ 附加监控通过 / ❌ 不通过（打回重做）

### ⑥ 灵汐验天 ── 验收层（坎水 1→6）

**代码位置：** `sixiang_guiyuan.py` → `_step_lingxi_yantian()`

**验收标准：**
- ✅ 原始裂隙已修复（`fissure_fixed`）
- ✅ 没有制造相邻新裂（`new_fissures` 为空）
- ✅ 回归测试通过（`regression_pass`）
- ✅ 全通过 = `all_pass`

---

### ⑦ 全体归元 ── 沉淀层（坤土 5→10）

**代码位置：** `sixiang_guiyuan.py` → `_step_quantiguiyuan()`

**归元三步：**
1. **提纯** — 从本次迭代中提炼可复用的模式（patterns）
2. **固化** — 更新 `system_evolution/evolution_archive.json`
3. **自指向分支** — 检查七步自身指标 → 不达标则生成自指向计划

**自指向触发条件：**

| 条件 | 描述 |
|:---|:---|
| 用户主动触发 | `force_self_refer=True` |
| 质量连续下降 | 某一步的 `quality_score` 连续2轮下降 |
| 周期性审视 | 每10轮自动触发一次 |
| 本轮失败 | 当前迭代验证未通过 |

**自指向执行：**
1. 读取最近N轮的自度量数据
2. 检测哪一步的指标在下降
3. 生成「七步升级方案」
4. 标记 `self_refer_applied = True`
5. 下一轮以升级后的七步进入

## 六、自指向能力（v2.0→v3.0核心进化）

### 自度量体系（SelfMetric）

```python
@dataclass
class SelfMetric:
    step_id: int          # 步骤编号 1-7
    name: str             # 步骤名称
    duration: float       # 耗时（秒）
    confidence: float     # 置信度 0-1
    quality_score: float  # 质量评分 0-1
    stability: float      # 稳定性 0-1
    timestamp: float      # 时间戳
```

### 自指向分支流程

```
第⑦步 全体归元 执行中：
    1. 检查触发条件（用户强制 / 质量下降 / 周期性 / 本轮失败）
       └─ 未触发 → 正常归档 → 回①
       └─ 触发 → 进入自指向分支：
          2. 生成自指向计划（检测哪一步指标最弱）
          3. 标记 self_refer_applied = True
          4. 归档时附带 self_refer 数据块
          5. 回①（下一轮以升级版七步执行）
```
