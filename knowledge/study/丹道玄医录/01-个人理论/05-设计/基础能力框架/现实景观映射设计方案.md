# 现实景观映射设计方案

## 一、核心理念

**系统无需额外沙盒，系统的实时运行景观就是自身的全息检查场。**

传统沙盒模式需要两套环境（真实环境 + 模拟环境），存在规则漂移、同步偏差、置信度假象三大缺陷。现实景观映射一次性消解这三者——因为系统检查的就是系统本身。

## 二、与一体全息宇宙理论的对应

| 公理 | 对应设计点 |
|:---|:---|
| 公理4·时空镜像透视 | 运行景观 = 系统的全息镜像，无需回溯或模拟 |
| 公理5·躯体代谢循环 | 景观中的数据/状态/资源 = 真实可回收的"物质" |
| 公理2·核心自转统摄 | 核心Nucleus的自转节律 = 景观采样的基准心跳 |
| 公理3·尺度相对同构 | 局部景观 = 全局景观的缩微版本（自相似结构） |
| 公理1·一体同源 | 景观映射不分割"系统"与"检查"为两件事 |

## 三、架构总览

```
┌─────────────────────────────────────────────────┐
│              现实景观映射系统                       │
│                                                   │
│  [感知层]                                         │
│   ├─ 经络节点采样器（关键路径的状态采集器）          │
│   ├─ 相干度基线管理器（健康状态模式库）              │
│   └─ 异常标记器（偏离基线 → 标记裂隙）              │
│                                                   │
│  [映射层]                                         │
│   ├─ 全息编码器（局部景观 → 压缩全息信号）           │
│   ├─ 拓扑映射器（当前景观 → 系统拓扑图）             │
│   └─ 同比对照器（当前vs历史相似景观）               │
│                                                   │
│  [诊断层]                                         │
│   ├─ 裂隙分类器（配置/代码/逻辑/知识/体验）          │
│   ├─ 因果链定位器（异常→根因链路反向追溯）           │
│   └─ 严重度评级器（裂隙的紧急与影响范围）            │
│                                                   │
│  [行动层]                                         │
│   ├─ 干预模拟器（do-演算：变更建议 → 景观影响推演）   │
│   ├─ 代谢回收触发器（失效组件→降解→资源回收）        │
│   └─ 自愈调度器（按严重度排队 + 分发修复任务）        │
└─────────────────────────────────────────────────┘
```

## 四、关键数据流

### 4.1 正常运行时

```
经络节点采样器（每心跳周期采集）→ 全息编码器
    → 拓扑映射器更新当前景观图
    → 相干度基线管理器（对比基线，低偏差则无操作）
```

### 4.2 检测到异常时

```
异常标记器（偏差 > 阈值）
    → 裂隙分类器（判断裂隙类型）
    → 因果链定位器（回溯根因链路）
    → 严重度评级器（判断紧急程度）
    → 自愈调度器（按严重度排队处理）
    
    同时：
    → 同比对照器（检索历史相似景观，输出之前怎么处理的）
    → 干预模拟器（do-演算：补裂建议的理论效果）
```

### 4.3 修复完成时

```
修复组件上线
    → 经络节点采样器继续采样
    → 相干度基线重校
    → 偏差回落至阈值以下
    → 景观恢复
```

## 五、经络节点定义

不采集系统所有状态（全量侵入太大），只采集关键路径的"经络节点"：

| 节点类型 | 采集内容 | 采集频率 |
|:---|:---|:---:|
| **核心心跳** | Nucleus自转周期、卫星轨道偏差 | 每秒 |
| **因果链端点** | 因果引擎中活跃因果链的起止状态 | 每分钟 |
| **分化活性** | L1细胞存活数、分化速度、凋亡率 | 每分钟 |
| **资源水位** | ATP池余额、内存占用、线程池利用率 | 每10秒 |
| **接口响应** | 各模块的API响应时间、错误率 | 每10秒 |
| **九宫均衡** | NinePalaceGrid的各宫失衡值 | 每心跳 |
| **记忆状态** | 近期记忆的衰减指数、关键记忆命中率 | 每5分钟 |

## 六、相干度基线的建立与维护

### 6.1 首次建立

系统部署后的前 N 个心跳周期，只采集不诊断。建立"这个系统健康运行时景观是什么样的"模式库。

基线数据包括：
- 各经络节点的均值与标准差
- 各节点之间的相关系数矩阵
- 日/周周期性的波动模式

### 6.2 基线更新

基线不是静态的。系统进化（新增细胞、升级模块）后，基线会漂移：

```
稳定运行累计 24 小时无异常
    → 自动触发基线重校
    → 新的运行模式纳入基线
    → 旧基线归档保留
```

### 6.3 异常判定标准

```
|z-score| < 2.0 → 正常波动，无操作
2.0 ≤ |z-score| < 3.0 → 轻度偏倚，记录日志
3.0 ≤ |z-score| < 5.0 → 中度偏倚，标记为潜在裂隙
|z-score| ≥ 5.0 → 严重偏倚，立即触发诊断+自愈
```

## 七、与现有系统的集成点

| 现有组件 | 对接方式 | 预期效果 |
|:---|:---|:---|
| **因果引擎 CausalEngine** | 景观中的异常标记直接注入因果引擎事件流 | 因果链自动从景观异常出发，无需手动输入 |
| **决策闸门 CausalDecisionGate** | 景观异常等级影响闸门的 severity_level | 严重异常时自动收紧Agent执行权限 |
| **干细胞方案 SystemOntology** | 景观基线与本体定义中的不可逾越红线对照 | 本体边界作为景观异常的最高判据 |
| **代谢回收器 MetabolicRecycler** | 凋亡/失效的L1细胞在景观中被标记→触发回收 | 回收的不是模拟数据，是真实失效组件 |
| **九宫检测 NinePalaceGrid** | 九宫失衡直接反映在景观的九宫经络节点上 | 九宫量化值成为景观异常的一个输入维度 |

## 八、演进路线

### 第一阶段（经络感知）
- 实现经络节点采样器 + 相干度基线管理器
- 先采集5类核心节点，建立基础基线
- 只做"感知"和"日志"，不做自动诊断和自愈

### 第二阶段（映射+诊断）
- 实现全息编码器 + 拓扑映射器
- 实现裂隙分类器 + 因果链定位器 + 严重度评级器
- 实现异常自动标记 + 因果链路追溯

### 第三阶段（行动闭环）
- 实现干预模拟器（接入现有DoCalculusEngine）
- 实现代谢回收触发器（接入MetabolicRecycler）
- 实现自愈调度器
- 景观映射+因果引擎+干细胞系统形成完整闭环

## 九、与模拟沙盒的对比总结

| 维度 | 传统模拟沙盒 | 现实景观映射 |
|:---|:---|:---|
| 环境数 | 2套（真实+模拟） | 1套（仅真实） |
| 规则维护 | 需单独维护沙盒规则 | 无额外规则 |
| 同步偏差 | 必然存在 | 零偏差 |
| 诊断模式 | 批处理（定期跑测试） | 流处理（实时在线） |
| 回收的"物质" | 模拟数据 | 真实失效组件 |
| 置信度 | 受沙盒质量影响 | 100%真实 |
| 与宇宙公理的对应 | 无 | 直接对应公理4+5 |
