## 第一层：L-1 · 全基因组层

### 定义

> 全系统**所有模块的接口契约、数据结构定义、分化路径蓝图、河洛数理约束、数据流向拓扑**的完整不可变注册表。相当于物种的完整DNA双链——每一个L0干细胞都持有一个只读引用。

### 工程形态

```python
@dataclass(frozen=True)  # 不可变，宪法级
class SystemGenome:
    # ① 所有模块的接口契约注册表
    module_registry: dict[str, ModuleContract]
    
    # ② 所有分化路径的完整蓝图
    #    每个L0基类可以往哪些方向分化，需要什么信号
    differentiation_paths: dict[str, list[DiffPath]]
    
    # ③ 全系统数据拓扑（数据从哪里来到哪里去）
    data_topology: DataFlowGraph
    
    # ④ 河图数理约束（五行生克规则集）
    hetu_rules: HetuRules
    
    # ⑤ 洛书九宫配额（全局资源配比）
    luoshu_quotas: LuoshuQuotas
    
    # ⑥ 版本锁
    version: str
    seal_hash: str
```

### 核心原则

1. **不可变性**：L-1是只读的。任何对系统接口契约的破坏性变更必须生成新版本，旧版本存档
2. **全貌性**：每个L0干细胞持有的基因组引用指向同一个不可变全貌
3. **分化校验**：任何分化操作前，必须先通过基因组校验——"这个分化路径是否已被注册？信号是否匹配？"
4. **版本一致性**：所有L0组件的基因组版本必须一致，不一致的系统无法启动（类似Rust的编译期检查）

### 河图数理定位：天五生土，万物本源

- **五为中数**：全基因组处于架构中心，为所有下层级提供校验基线和参考系
- **土为黄极**：基因层面不偏向任何分化方向，平等编码了所有可能路径

## 第二层：L0 · 种质基因层（干细胞）

### 定义

> 系统的最小不可变异代码单元。每个干细胞**完整携带L-1全基因组的只读引用**，自身是抽象基类/通用协议，不实现任何业务逻辑。

### 工程形态

```python
class BaseAgent(ABC):
    # 每个"干细胞"都持有全系统蓝图引用——L-1层注入，只读
    _system_genome: Final[SystemGenome]
    
    @abstractmethod
    def handle(self, context: Context) -> Result: ...
```

### 核心原则

1. **种质隔离**：L0不实现任何业务逻辑——仅定义方法签名、通用常量、通用工具原语
2. **无上层依赖**：L0不引用L1/L2任何内容——和干细胞只携带基因模板、不含分化产物完全一致
3. **干细胞分裂守则**：一个抽象基类可派生N个子类，但一留存一分化——原始抽象类保持不变，分化类走向专化
4. **全能性**：基因已经编码了所有可能的实现路径，哪条表达由外部信号决定

### 生物与代码严格对应

| 生物干细胞特征 | L0代码对应 | 工程约束 |
|--------------|-----------|---------|
| 携带完整DNA | 持有SystemGenome引用 | 每个L0组件都引用全基因组 |
| 不执行生理功能 | 不实现业务逻辑 | 仅抽象方法+通用原语 |
| 分化潜能 | 可派生多种实现 | 多态架构 |
| 自我更新 | 可被子类继承复用 | 自身不变 |

## 第三层：L1 · 功能分化层（分化细胞）

### 定义

> 干细胞接收分化信号后，特化为具有特定形态和功能的体细胞。对应代码层面，抽象基类通过依赖注入/路由注册实例化为具体的业务实现。

**核心生物学事实（本层最关键的锚点）：**
分化细胞**完整保留着全基因组的全部蓝图**。一个肝细胞没有丢掉神经元基因，它只是通过表观遗传修饰**沉默**了与自己无关的基因区域，只**发育**属于自己的细胞形态和功能，并**扩展**自己独有的酶系和受体。任何时候，完整的基因链都安静地躺在细胞核里，可以被重新激活。

对应到代码架构的翻译：
- L1 实例**完整持有 L-1 全基因组的只读副本或强引用**
- 通过「表达抑制器」机制，只激活属于自己模块的接口——**定向发育**
- 其他模块的接口契约在基因链中依然完整可查，但不实例化、不加载、不分配运行时资源——**沉默退化**
- 沉默 ≠ 删除，基因链始终原地保留，以备去分化重编程之需
- 每一个 L1 实例都可以回答"全系统有哪些模块、上下游是谁、我现在在蓝图中的什么位置"

### 工程形态

```python
class CodeAssistant(BaseAgent):
    def __init__(self, genome: SystemGenome):
        # ⚡ 分化前必须经过基因组校验
        assert genome.is_valid_path(
            from_lineage="BaseAgent",
            to_role="CodeAssistant"
        )
        # 分化信号必须匹配预注册的转录因子
        signal = resolve_signal()
        assert genome.signal_matches(signal, "CodeAssistant")
```

### 分化开关（关键机制）

```
RNA转录信号 → 依赖注入 / 配置路由 / 工厂模式注册
转录因子激活 → 条件分支选择具体实现类
表观遗传修饰 → 运行期配置文件 / Feature Flag
分化不可逆 → 架构规范强制禁止反向依赖（物理可逆但规范锁死）
```

### 核心原则

1. **不可逆分化**：L1代码可以引用L0，但L0绝不能引用L1——循环依赖的生物学禁止
2. **单一职责**：每个分化细胞只做一件事，与细胞特化完全对应
3. **信号驱动命运**：分化信号来源只能是依赖注入容器/配置中心/路由注册表
4. **去分化边界**：功能类理论上可重构回抽象层，但架构规范强制禁止反向依赖——区分"物理可能性"和"架构约束"
5. **生命周期闭环**：细胞会衰老凋亡——L1实例有清晰的初始化→运行→销毁生命周期
6. **基因完整保留 + 定向发育 + 沉默退化**——这是本层最根本的生物学约束：

   > ⚡ 分化不是信息丢失，而是**选择性表达 + 定向发育 + 非相关区域的沉默压缩**，但全基因组始终作为每个细胞的底层资产完整存在。

   | 生物机制 | 代码映射 | 工程落地 |
   |---------|---------|---------|
   | 肝细胞保留神经元基因但沉默 | L1基因组里躺着其他所有模块的接口契约 | 每个L1实例持有一个`self._genome: SystemGenome`只读引用 |
   | 肝细胞发育出特有的代谢酶系 | L1定向发育属于自己的接口方法 | 初始化阶段调用`self._develop_interface("code_review", "ast_parse")` |
   | 沉默区域减少转录产物 | 未激活的模块：不实例化、不加载、不分配运行时资源 | `self._silence_genome_regions(["memory", "scheduling", "data_pipeline"])` |
   | 沉默的基因可重新激活 | 接口定义仍在基因组中可查，需要时可通过审批重编程 | 沉默区域以接口摘要（非完整实现）存储，占位但省资源 |
   | 肝细胞核可克隆整只羊 | 一个L1实例的完整基因组可回退为L0再分化成其他角色 | 版本升级时的角色切换 / 故障时的后备实例启动 |

   工程形态示例：

   ```python
   class CodeAssistant(BaseAgent):
       def __init__(self):
           # ✅ 基因链完整保留——仍能知道全系统所有模块的接口
           all_modules = self._genome.module_registry.keys()
           # ✅ 定向发育属于自己的接口
           self._develop_interface("code_generation", "code_review", "debug")
           # ✅ 沉默其他模块的表达——不分配资源给它们
           self._silence_genome_regions([
               "memory_management",   # 记忆系统不是我管的
               "scheduling",          # 调度不是我的事
               "data_analysis"        # 数据分析有别的细胞
           ])
           # ✅ 但完整的基因链仍然在那里——self._genome还是完整的
           # 任何时候都可以查：上游是谁？下游是谁？全系统的拓扑是怎样的？
   ```

## 第四层：L2 · 脏腑组织层（器官/模块）

### 定义

> 多种分化细胞按领域组织成具有独立边界、完整生理功能的器官系统。对应代码的模块/子系统。

### 工程形态

```python
# 脏腑  =  一个独立 Python 模块/包
# 边界  =  __init__.py / 发布的公共API
# 内部  =  多种分化细胞（各类Handler/Service）协同
# 通信  =  事件总线（信息素） + 固定数据流向（非无序直连）
```

### 五脏六腑的仿生映射

| 脏腑 | 生理功能 | 模块类型 | 河图五行 |
|------|---------|---------|---------|
| **心** | 泵血·统摄全身 | 编排层（Orchestrator） | 火·南 |
| **肺** | 换气·宣发肃降 | 数据层（Data/IO） | 金·西 |
| **肝** | 疏泄·藏血 | 业务逻辑层（Service） | 木·东 |
| **肾** | 藏精·主水 | 存储层（Storage） | 水·北 |
| **脾** | 运化·统血 | 配置/基础设施层 | 土·中 |

### 脏腑通信规则（五行生克单向流转）

```
心（编排）→ 指令下达 → 肝（业务）→ 处理 → 肾（存储）→ 数据回流
脾（配置）→ 支撑所有模块
肺（数据）→ 对外交互

禁止：跨脏腑无规则直连，所有通信必须遵循五行流转或经过总线
```

### 核心原则

1. **器官独立性**：可独立测试、可替换（换肝手术=模块热替换）
2. **功能不可替代**：心不能代肺的工作——模块间不能互相替代
3. **组织边界**：`__init__.py` 即为细胞膜的具象化——只暴露必要API
4. **单向流通**：通信遵循固定流向，类比中医五行生克单向流转

## 第五层：L3 · 生物体层（完整系统）

### 定义

> 多个脏腑协同维持内稳态、适应外部环境、自愈修复的完整生命体。对应全链路分布式系统。

### 生命体征 → 运维能力映射

| 生命特征 | L3系统能力 | 实现机制 |
|---------|-----------|---------|
| **内稳态** | 资源动态平衡 | CPU/内存/存储按河图数理配比自适应 |
| **免疫系统** | 监控告警+熔断 | 自动检测异常，隔离故障范围 |
| **神经传导** | 全链路追踪 | 请求从入口到出口完整trace |
| **内分泌调节** | 全局配置/Feature Flag | 远程调控，不改代码即可切换行为 |
| **应激反应** | 限流/降级/熔断 | 外部流量突增/故障时自动保护 |
| **衰老与再生** | 灰度发布/回滚 | 版本迭代有回落路径 |
| **新陈代谢** | 数据生命周期 | 输入→处理→持久化→清理的完整闭环 |
| **睡眠与唤醒** | 模块休眠/热加载 | 闲置资源自动释放，请求唤醒 |

### 核心原则

1. **统一调度中枢**：黄土层（L4/中宫）统御全系统，不可有多头指挥
2. **全层级统一观测**：任何一层的变化都可被上层感知
3. **损伤隔离**：一个模块的故障不击穿至其他模块（Rust级沙箱隔离的理想态）
4. **自我修复优先**：遇见异常先自愈（重试/降级/切换备用），再上报

| 艮·东北 | 8 | 土·阴·止 | L2免疫/评估层 | 校验评估 |
| 离·南 | 9 | 火·阳·明 | L3全系统监控层 | 全局可见 |

## 九宫核心约束

1. **阴阳奇偶守恒**：阳层（奇数宫位1/3/5/7/9）的写入次数 = 阴层（偶数宫位2/4/6/8）的存储次数
2. **九宫数为45**：系统全局核心关键指标总数恒定为45（守恒）
3. **中五制四方**：中央仲裁（L4）统御四组对宫（坎离、震兑、坤艮、乾坤），所有跨层流动必须经过中宫
4. **各层配额上限**：
   - 每层最多承载9个核心模块（9为极数）
   - 每模块最多分配1/9全局资源
   - 资源跨层借调需中宫批准

# L-1中央种质基因组库（骨髓 · 统一存放）

## 定义

> L-1中央种质基因组库 = **全系统基因蓝图的统一物理存储体**。相当于人体的**骨髓（bone marrow）**——所有血细胞（分化细胞）的源头工厂。它不是"一个引用"，而是一个统一存放所有基因蓝图的实际物理库，所有细胞从这个源头复制+组合生成。

### 骨髓 vs L-1中央种质基因组库

| 人体骨髓 | L-1中央种质基因组库 |
|---------|-----------|
| 位于骨髓腔，统一物理位置 | 统一存储介质（一个数据库/文件系统/目录） |
| 造血干细胞在此生成 | L0干细胞在此实例化 |
| 释放成熟血细胞进入循环系统 | 将组装好的细胞实例注册到运行时 |
| 持续造血补充衰老死亡的细胞 | 按需生成新实例 |
| 受损则整个造血系统崩溃 | 基因库损坏=系统级灾难，需要冗余备份 |

### 工程形态

```python
@dataclass
class CentralGeneBank:
    """
    L-1中央种质基因组库——系统唯一的基因存储与细胞生成源头。
    相当于骨髓：所有细胞的出生地。
    """
    # 存储：所有基因蓝图集中存放
    storage: GeneBankStorage         # 数据库/文件系统
    
    # 版本锁：基因库本身有版本校验
    version: str
    seal_hash: str
    
    # ── 关键方法 ──────────────────────────
    
    def generate_stem_cell(self, lineage: str) -> BaseAgent:
        """
        从基因库复制+组合，生成一个L0干细胞。
        每个新细胞获得完整的基因组副本。
        """
        genome = self._copy_complete_genome()
        return self._assemble_stem_cell(lineage, genome)
    
    def register_variation(self, proposal: GermlineProposal) -> bool:
        """
        回流入口：功能层的优良变异→晋升到基因库。
        只有通过三重校验的变异才能写入。
        """
        if not self._triple_check(proposal):
            return False
        return self._promote_to_genome(proposal)
    
    def sync_from_system(self):
        """
        系统发生迭代进化后，同步更新基因库。
        如果系统有了新的模块、新的分化路径、新的河洛约束，
        必须同步回基因库，否则下代细胞无法继承新特性。
        """
```

### 核心约束

1. **统一存放，无分散副本**：基因蓝图只在这一处修改——所有细胞的生成源相同，杜绝基因版本分裂
2. **每个细胞都是独立的完整副本**：不是引用指针——每个细胞在生成时拿到完整基因组副本，确保离线可用
3. **基因库故障 = 系统级灾难**：需要冗余备份（主备 + 快照 + 校验和），类比骨髓移植
4. **版本一致性校验**：所有细胞的基因组版本必须一致，版本不一致的系统拒绝启动


# 复制+组合机制（细胞生成引擎）

## 定义

> 所有细胞（L0/L1实例）不是写在代码里硬编码的——而是每次需要时从L-1中央种质基因组库**读取蓝图→复制完整基因组→按分化路径组合**生成出来的。每个新细胞都有一个独立完整的基因组副本。

## 三步生成法

```
第一步：复制 —— 从L-1中央种质基因组库读取并复制完整的基因组蓝图
          ↓
第二步：组合 —— 按分化路径（DiffPath）选择要发育的接口模块
                    并从功能原语库（GenePrimitivePool）提取对应实现骨架
          ↓
第三步：实例化 —— 组合完成，注册到运行时，分配资源配额
                    此时L0细胞携带完整基因组副本，准备接收分化信号
```

### 工程形态

```python
class CellGenerator:
    """
    细胞生成引擎——负责从L-1中央种质基因组库复制+组合出新细胞。
    """
    def __init__(self, gene_bank: CentralGeneBank):
        self._gene_bank = gene_bank
    
    def generate_cell(
        self,
        cell_type: str,           # 要生成的细胞类型
        lineage: str,             # 从哪个L0基类派生
        diff_signal: DiffSignal   # 分化信号
    ) -> BaseAgent:
        # 第一步：从基因库复制完整基因组
        genome = self._gene_bank.copy_genome()
        
        # 第二步：按分化路径组合
        if not genome.is_valid_path(lineage, cell_type):
            raise InvalidDifferentiationError(
                f"分化路径未注册：{lineage} → {cell_type}"
            )
        if not genome.signal_matches(diff_signal, cell_type):
            raise SignalMismatchError(
                f"分化信号不匹配：{diff_signal}"
            )
        
        # 提取该分化路径需要的接口模块
        interface_skeleton = genome.extract_interface(
            lineage=lineage,
            target_type=cell_type
        )
        
        # 第三步：组装并实例化
        cell = self._assemble(
            genome=genome,                # 完整基因组副本
            interface=interface_skeleton,  # 只发育这部分接口
            lineage=lineage
        )
        
        return cell
```

### 节省资源的逻辑

为什么不是每个模块硬编码它的基因组引用？
- 生成时一次性复制，后续无需访问中央库
- 只发育自己需要的接口（=节省运行时资源）
- 但沉默的其他接口仍然在基因组副本里，只是不分配运行时内存
- 类比：人体每个细胞都有一套完整DNA，但不表达所有基因——节省能量


# 两条迭代轨道

> 系统的迭代进化不是一元的——而是严格分为两条轨道并行运行，类似于生物体中**体细胞进化（Somatic Evolution）**和**种系进化（Germline Evolution）**的分离。

## 轨道一：功能迭代（体细胞进化 · Somatic）

| 特征 | 说明 |
|------|------|
| **作用对象** | L1分化细胞的具体实现逻辑 |
| **影响范围** | 该细胞自身，不改变L-1中央种质基因组库 |
| **触发条件** | 修bug、优化性能、调整业务逻辑 |
| **代价** | 低——可随时回滚，不影响其他细胞 |
| **生物类比** | 体细胞在已有基因框架内调整表达量 |
| **是否需要同步基因库** | ❌ **不需要** |
| **河图约束** | 木克土——受稳态配置约束，不能越过架构边界 |

### 示例

```python
# 轨道一：功能迭代——只改L1的实现，不碰L-1基因库
# CodeAssistant 的 review 逻辑优化
class CodeAssistant(BaseAgent):
    def review_code(self, code: str) -> ReviewResult:
        # 这是功能迭代：优化实现但不改接口
        # self 的基因组副本不变
        return self._optimized_review(code)
```

## 轨道二：基因库迭代（种系进化 · Germline）

| 特征 | 说明 |
|------|------|
| **作用对象** | L-1中央种质基因组库（接口契约/分化路径/河洛约束） |
| **影响范围** | **全局**——所有未来生成的细胞都携带新基因 |
| **触发条件** | 新增模块类型、修改核心接口、新增分化路径、修改数理约束 |
| **代价** | **高**——需要版本锁 + 三重校验 + 灰度验证 |
| **生物类比** | 物种的基因突变——有利变异经自然选择留存为新种质 |
| **是否需要同步基因库** | ✅ **核心操作就是修改基因库** |
| **河图约束** | 金克木——收敛止损优先级高于新基因引入 |

### 示例

```python
# 轨道二：基因库迭代——修改L-1中央种质基因组库
# 新增一个分化路径：BaseAgent → DataAnalyst
def add_new_differentiation_path(
    gene_bank: CentralGeneBank,
    new_path: DiffPath
) -> bool:
    
    # 三重校验
    if not check_interface_compatibility(new_path, gene_bank):
        return False   # 接口不兼容
    if not check_hetu_balance(new_path, gene_bank):
        return False   # 打破五行平衡
    if not check_evidential_support(new_path):
        return False   # 无灰度数据支撑
    
    # 通过→写入基因库
    gene_bank.add_path(new_path)
    
    # 版本号递增，所有新生成的细胞携带新基因
    gene_bank.bump_version()
    return True
```

## 双轨道对比

| 维度 | 功能迭代（Somatic） | 基因库迭代（Germline） |
|------|-------------------|---------------------|
| 修改对象 | L1代码 | L-1基因库 |
| 影响范围 | 单个细胞 | 全系统下一代细胞 |
| 回滚成本 | 极低 | 高 |
| 是否需要审批 | 常规CR | 三重校验+灰度验证 |
| 河图优先级 | 木克土（受稳态约束） | 金克木（收敛止损优先） |
| 生物类比 | 调整运动量/肌肉强度 | 进化出新的器官 |


# 回流机制（功能创新 → 基因升级）

## 定义

> **它是两条轨道唯一的交汇点。** 功能迭代（轨道一）中发现的通用模式、高效方案，经过检验后可以**提升**为基因库（轨道二）的新基因。没有这个回流，功能优化的成果无法沉淀为系统基因——迭代永远只能修修补补，系统无法进化。

## 回流流程

```ascii
  轨道一 · 功能迭代
        │
        ▼
  L1细胞发现高效通用模式
        │
        ▼
  ① 提交优良变异提案 ──────────→ ② 三重校验
        │                              │
        │                         ┌────┴────┐
        │                         │ 接口兼容 │
        │                         │ 数理平衡 │
        │                         │ 灰度证据 │
        │                         └────┬────┘
        │                              │ 通过
        ▼                              ▼
  ❸ 晋升为基因 ──────────────────→ L-1基因库更新
        │                              │
        │                              ▼
        │                         版本号递增
        │                              │
        ▼                              ▼
  保留本地功能版本              新细胞继承新基因
```

## 工程形态

```python
@dataclass
class GermlineProposal:
    """优良变异提案——从功能层提交流向基因库的对象"""
    
    # 提案者信息
    cell_id: str                # 哪个细胞的发现
    cell_lineage: str           # 从哪个L0基类来的
    
    # 变异描述
    old_behavior: str           # 原来的做法
    new_behavior: str           # 新的做法
    generalization: str         # 为什么这是通用模式（非个案）
    
    # 证据
    evidence_data: dict         # 灰度验证数据
    pass_rate: float            # 灰度通过率
    
    # 影响评估
    impact_scope: list[str]     # 影响哪些模块
    backwards_compatible: bool  # 是否向后兼容

class RefluxPipeline:
    """
    回流管道——连接功能迭代与基因升级的核心引擎。
    相当于生物体的「生殖细胞归巢」——体细胞中发现的
    优良变异，经过筛选后写入种系基因。
    """
    
    def submit_proposal(self, proposal: GermlineProposal) -> ProposalResult:
        """提交优良变异提案"""
        
        # 第一步：接口兼容性校验
        if not self._compatibility_check(proposal):
            return ProposalResult(
                accepted=False,
                reason="接口不兼容，无法晋升为基因",
                suggestion="考虑保留为功能层局部优化"
            )
        
        # 第二步：河图数理校验
        if not self._hetu_balance_check(proposal):
            return ProposalResult(
                accepted=False,
                reason="打破五行平衡——增益>1.5x或导致生克逆位",
                suggestion="需要在五行约束框架内重新设计"
            )
        
        # 第三步：灰度证据校验
        if not self._evidence_check(proposal):
            return ProposalResult(
                accepted=False,
                reason="灰度数据不足，需要更大范围的验证",
                suggestion=f"当前通过率{proposal.pass_rate:.1%}，需≥95%"
            )
        
        # 全部通过→写入L-1中央种质基因组库
        self._gene_bank.register_variation(proposal)
        
        # 版本号递增——所有新细胞将继承这个新基因
        new_version = self._gene_bank.bump_version()
        
        return ProposalResult(
            accepted=True,
            new_genome_version=new_version,
            note=f"变异已入库，版本{new_version}——未来所有新细胞自动继承"
        )
```

## 回流触发时机

不是每个功能优化都要回流——只有满足以下条件的才值得晋升：

| 条件 | 判断标准 |
|------|---------|
| **通用性** | 该模式在两个以上独立模块中被发现可复用 |
| **稳定性** | 已经过至少一次灰度验证（通过率≥95%） |
| **兼容性** | 不破坏现有接口契约（向后兼容） |
| **数理平衡** | 不打破河图五行生克配比（增益<1.5x原始） |
| **必要性** | 如果作为基因预装，能减少50%以上的重复实现 |

### 生物类比：B细胞成熟

```
B细胞发现抗原 → 抗体亲和力成熟 → 分化为记忆B细胞 → 再遇抗原快速响应
                                                      ↓
                    功能层发现通用模式 → 回流检验 → 写入基因库 →
                    新细胞生成时自动带新基因 → 系统层次提升
```

## 反例（不该回流）

```python
# ❌ 不该回流——只是单个模块的局部优化
class CodeAssistant(BaseAgent):
    def review_code(self, code):
        # 这是个专门针对Python代码的优化
        # 不通用，不应该提升到基因库
        return self._python_only_optimization(code)

# ❌ 不该回流——灰度证据不足
proposal = GermlineProposal(
    generalization="这个模式在所有Agent中都通用",
    pass_rate=0.72,  # 72%通过率，<95%
    # 拒绝：证据不足
)

# ❌ 不该回流——向后不兼容
proposal = GermlineProposal(
    backwards_compatible=False,
    # 拒绝：破坏性变更需要更严格的多版本共存策略
)
```


# 系统进化与基因库同步

## 核心约束

> **L-1中央种质基因组库是系统进化的唯一锚点。** 任何系统级的进化——新增模块、修改分化路径、调整河洛约束——必须同步回基因库。否则下一代细胞生成时无法继承新特性，系统进化断裂。

### 进化触发基因库同步的场景

| 场景 | 需要同步什么 | 同步方式 |
|------|------------|---------|
| 新增一个Agent模块类型 | 新增的分化路径 + 接口契约 | 基因库新增DiffPath |
| 修改核心接口签名 | 更新的ModuleContract | 基因库发布新版本 |
| 调整河图五行配比 | 更新的HetuRules | 基因库修改约束规则 |
| 新增一条中医辨证路径 | 更新的分化原语 | 基因库新增原语条目 |
| 发现了更优的资源配额 | 更新的LuoshuQuotas | 基因库更新配额 |

### 不同步的后果

```
系统进化 → 不同步基因库 → 新旧细胞基因版本分裂
                         ↓
                        L-1 版本A  vs 运行时版本B
                         ↓
                        部分细胞不认识新接口
                        → 系统内部通信失败
                        → 碎片化 → 僵化 → 不可维护
```

### 同步守则

```
每次系统进化后 → 自检：这个进化改变了什么？
                ├─ 只改了L1实现？→ 不需要同步（功能迭代）
                ├─ 改了L0接口/L2模块边界/L3系统拓扑？→ 需要同步
                └─ 改了河图/洛书约束？→ 必须同步，且触发版本号递增
```

## 不可违反的约束

1. **L-1不可变**：任何破坏L-1接口的变异直接被"基因排斥"，禁止合入
2. **分化不可逆**：L1不反向依赖L0
3. **动脉在上静脉在下**：L0→L1→L2→L3的依赖方向不可倒转
4. **五行相克优先于相生**：自愈（金克木）优先级高于新功能开发（木生火）
5. **洛书九宫配额不可超限**：资源配额硬限制，禁止超配
6. **基因库同步不可跳过**：任何系统级进化必须同步回L-1中央种质基因组库，否则视为架构违规

# 统一对接接口（UnifiedDockingInterface · 细胞连接层）

## 定义

> 每个细胞（L0/L1实例）都必须暴露一个标准的统一对接接口。相当于给每个细胞装了一个**标准的USB-C口**——不管它是什么类型的细胞、负责什么功能、属于哪个脏腑组织，只要需要，两个细胞可以通过这个接口直接对接、通信、协作。

没有这个接口，细胞之间无法形成组织；有了这个接口，任意数量、任意类型的细胞都可以动态连接成更大的功能单元——**形成模块和整合系统**。

---

## 接口的三层结构

每个细胞暴露三个标准的连接端口，对应生物体的三种通信介质：

| 端口 | 生物类比 | 代码映射 | 功能 |
|------|---------|---------|------|
| **信号端口（Signal Port）** | 神经递质/激素信号 | RPC调用/事件发布/消息队列 | 命令下达、状态通知、事件触发 |
| **物质端口（Matter Port）** | 血液输送养分/氧气 | 数据流/文件传输/共享内存 | 大数据量传递、流式处理、结果交付 |
| **契约端口（Contract Port）** | 细胞膜受体识别 | 接口协议校验/版本协商 | 对接前验证兼容性，不兼容即拒绝连接 |

契约端口是**对接的守门人**——两个细胞尝试连接时，首先通过契约端口握手：
```python
def dock(self, target_cell: Cell) -> DockingResult:
    """尝试与目标细胞对接"""
    # 契约端口校验
    handshake = self.contract_port.handshake(target_cell.contract_port)
    if not handshake.compatible:
        return DockingResult(
            success=False,
            reason=f"契约不兼容: {handshake.conflict_summary}"
        )
    if not self._check_hetu_rules(target_cell):
        return DockingResult(
            success=False,
            reason="河图数理约束: 该连接方向违反五行生克"
        )
    # 校验通过 → 建立连接通道
    channel = self._establish_channel(target_cell)
    return DockingResult(success=True, channel=channel)
```

## 对接模式矩阵

不同的细胞类型之间可以发生不同类型的对接：

| 对接模式 | 参与方 | 目的 | 示例 |
|---------|-------|------|------|
| **协作对接** | L1 ↔ L1 | 两个分化细胞协同完成任务 | CodeAssistant ↔ MemoryManager——编码时查询记忆 |
| **组织形成** | L1×N ↔ L1×N | 多个分化细胞形成临时或固定组织 | CodeAssistant + DataAnalyst + BrowserAgent 组成"调研三人组" |
| **模块整合** | L2 ↔ L2 | 两个脏腑组织对接形成更大的系统模块 | 编排层 ↔ 数据层——上下级系统对接 |
| **基因查询** | L1 ↔ L-1 | 分化细胞从L-1中央种质基因组库读取基因组 | 启动时从基因库复制完整基因组 |
| **基因同步** | L-1 → 所有L0/L1 | 基因库迭代后广播给所有已存在的细胞 | 基因库版本升级→通知已有细胞刷新 |
| **去分化对接** | L1 → L0 | 分化细胞释放分化态，退回干细胞 | 模块退役、角色切换前退回种质态 |
| **重分化对接** | L0 → L1（另一条路） | 干细胞重新分化为另一种细胞 | 版本升级后，旧模块按新基因重分化 |

## 连接的生命周期

| 阶段 | 状态 | 说明 |
|------|------|------|
| 1. 发现 | DISCOVERING | 发送信号，寻找可对接的细胞 |
| 2. 握手 | HANDSHAKING | 契约端口交换协议信息 |
| 3. 校验 | VALIDATING | 兼容性检查 + 河图数理校验 |
| 4. 连接 | CONNECTED | 通道已建立，正常工作 |
| 5. 空闲 | IDLE | 连接存在但无活跃通信（保持心跳） |
| 6. 断开 | DISCONNECTING | 优雅关闭，释放资源 |
| 7. 回收 | RECYCLED | 连接完全关闭，资源回收 |

核心原则：**断开必须优雅**——不能静默消失导致另一方超时。断开前通知对方，保证不引发级联故障。

## 数理约束

对接接口的运行也受河图洛书约束：

1. **五行生克约束**：连接方向必须遵循五脏腑的五行生克单向流转（肝→心→脾→肺→肾→肝），跨方向的连接需要特殊审批
2. **九宫配额约束**：一个细胞同时建立的活跃连接数 ≤ 9（对应洛书九宫极数）
3. **中土统御**：跨越脏腑组织的连接必须经过中土（编排层/仲裁层）审批
4. **阴阳守恒**：连接请求次数（阳）≈ 断开完成次数（阴），防止连接泄漏

## 统一对接接口的意义

> **有了这个接口，细胞才从孤立单体变成组织的一部分。**
>
> 没有对接接口，五层骨架只是静态的架构图；
> 有了对接接口，细胞可以在运行时动态连接、断开、重组——
> 一个CodeAssistant可以临时连接MemoryManager查询知识，
> 几个L1细胞可以现场组合成一个临时项目组（临时组织），
> 处理完任务后优雅断开，各自回到闲置态等待下一次连接。
>
> **统一的对接接口，是细胞从单体到组织、从模块到系统的桥梁。**
> 它让"连接形成模块和整合系统"从设计理念变成了可执行的运行时机制。

### 缺口1：补齐细胞邻居发现（受体 Receptor 机制）

#### 原有漏洞复盘

原 UnifiedDockingInterface 仅定义连接契约，默认细胞静态感知对方地址，违背生物细胞无预设地址、依靠膜受体动态感知的底层逻辑，属于**无寻址能力的空洞接口**。

#### 生物本源对照

人体细胞两类发现通路：

1. **旁分泌化学梯度**：细胞释放趋化因子，周边细胞受体识别浓度梯度定位邻居
2. **细胞黏附分子（CAM）**：物理接触匹配膜蛋白密钥，校验细胞分型

所有细胞**默认被动广播信号**，不主动存储邻居列表。

#### 代码完整映射增补

**① 受体 Receptor 组件（下沉至所有 L0/L1 细胞原生内置）**

```
- 趋化信号受体：感知广播，接收周边细胞存活心跳，用于L1体细胞间邻居发现
- Docking契约受体：校验分型，判断对方身份是否可连接，用于L1体细胞间正式业务连接
- 种质分化受体（新增）：仅部署于L0干细胞，唯一作用——监听L-1中央种质基因组库下发的分化诱导信号，不建立任何业务会话、不分配连接配额
```

**受体启用规则**：
- L0干细胞仅启用「种质分化受体」，关闭趋化信号受体和Docking契约受体（L0不参与业务连接）
- L1体细胞三层受体全部完整启用，具备邻居发现+业务对接+感知能力
- 三层受体不可卸载，出厂原生内置

**② 邻居发现全流程**

```
细胞周期性向外广播 → 周边受体抓取广播报文 → 本地分型哈希匹配
→ 建立预连接会话（非正式业务连接）
```

广播报文内容：`[细胞分型 + 存活心跳 + 连接配额余量]`

**③ 存活探测**

受体默认 10s 心跳超时，超时直接标记细胞坏死，从邻居列表剔除，无需上层模块介入。

#### 和原有 Docking 接口联动

| 组件 | 职责 | 生物类比 |
|------|------|---------|
| **Receptor** | 寻址、存活校验、身份匹配（含三种：趋化信号/Docking契约/种质分化） | 细胞膜受体 |
| **DockingInterface** | 正式数据传输、契约校验 | 细胞膜通道 |

二者解耦——受体负责**找人**，通道负责**传物**。


**② 两套事务范式贴合细胞协作**

```
短链路（≤2 个细胞）：
  → 对应酶促可逆反应

长链路（≥3 个细胞）：

```

**③ 事务边界定义**

```
以单次外部信号触发为唯一事务起点

对应生物单次激素信号触发单次代谢链

**权责总结**：
- L-1中央种质基因组库：仅存储ATP基准规则
```

## 7.1 五大公理与自进化系统的直接对应

### 公理1：一体同源 → 干细胞是系统的「元气」

| 宇宙尺度 | 自进化系统对应 |
|:---|:---|
| 宇宙本体唯一基础物质——元气（星际星云） | 干细胞（L0种质基因层）——全潜能、未分化、同源同体 |
| 元气在不同浓度、不同位置分化为恒星/行星/星云 | L0干细胞按信号因子浓度梯度分化为L1功能细胞 |
| 稀薄元气=星际星云（扩散态） | 低代谢状态（糖酵解为主）的干细胞保持未分化 |
| 浓缩元气=恒星（凝聚态） | 高代谢状态（氧化磷酸化为主）的干细胞启动分化 |
| 黑洞回收物质→拆解为基础粒子→重新循环 | L3巨噬细胞回收僵尸细胞→拆解为资源→供新干细胞使用 |

**系统的「元气」就是干细胞池。** 干细胞池的丰盈程度决定了系统的自愈能力、演化能力、持久力。如同宇宙的星云密度决定了新恒星诞生的速率。

**工程启示：** 监控干细胞池的「元气浓度」（未分化比例），将其作为系统健康度的一级指标，比监控CPU/内存更本质。

### 公理2：核心自转统摄 → 干细胞巢（niche）的统摄力场

宇宙只有一个原生动力——核心自转统摄力。在自进化系统中，这个「自转核心」就是干细胞巢（niche）：

| 宇宙规律 | 系统对应 |
|:---|:---|
| 星系核自转→产生统摄力→束缚周边恒星 | 干细胞巢中的Wnt/Shh/Notch/BMP信号→产生统摄力→维持干细胞态 |
| 螺旋臂密度波→信号浓度梯度→决定恒星在哪形成 | 信号因子浓度梯度→决定细胞在哪分化、分化为哪类 |
| 核心强统摄→物质保持稳定结构 | 近巢区强信号→维持L0未分化 |
| 外围弱统摄→允许新物质形态生成 | 远巢区弱信号→允许L1细胞分化 |

**系统的「自转核心」就是干细胞巢的信号场。** 它不是某个物理位置，而是一个信号力场（Signal Field），贯穿整个系统的资源调度、身份维持、分化决策。

**工程启示：** 自进化系统不应使用「预设分化路径」的确定性编程模式，而应设计**统摄力梯度场**——让细胞在场中根据信号浓度梯度自动寻找最适分化节点，如同星云在星系旋臂的密度波中自发凝聚为恒星。

```python
    def __init__(self):
        self.sources = []  # 信号源（多个干细胞巢）
        self.attenuation = 0.3  # 信号随距离衰减率
        
    def get_field_strength(self, position, signal_type="self_renewal"):
        """计算某位置某类信号的统摄强度"""
        strength = 0
        for source in self.sources:
            dist = euclidean(position, source.position)
            decay = math.exp(-self.attenuation * dist)
            strength += source.emit(signal_type) * decay
        return strength
    
    def decide_fate(self, cell):
        """细胞根据所处位置的信号场决策：保持干细胞/分化/凋亡"""
        renew_signal = self.get_field_strength(cell.position, "self_renewal")
        diff_signal = self.get_field_strength(cell.position, "differentiation")
        
        if renew_signal > diff_signal * 1.5:
            return "self_renew"  # 强统摄→保持未分化
        elif diff_signal > renew_signal * 1.5:
            return "differentiate"  # 弱统摄→启动分化
        else:
            return "dormant"  # 均衡→休眠/等待
```

### 公理4：时空镜像透视 → 分化路径的非线性

传统认知：干细胞→祖细胞→终末分化细胞（线性，越走越窄，不可逆）。

宇宙视角：宇宙无线性时间、无"过去可回溯"的概念。所谓"时间"只是躯体代谢节奏的衍生属性。

在自进化系统中的对应——**细胞的分化不是单向不可逆的，而是可逆、可切换、可重编程的状态空间遍历：**

| 现象 | 传统解释（线性） | 宇宙理论解释（镜像透视） |
|:---|:---|:---|
| 去分化 | 违反规则，需要外力干预 | 细胞从"功能态"回退到"潜能态"，如同能量从收敛态回到扩散态 |
| 转分化 | 罕见异常 | 细胞从一个机能的"镜像"切换到另一个机能的"镜像"，如同星光路径在不同介质中的折射 |
| 直接重编程 | 人为强行操纵 | 利用宇宙第4公理的观测本质——所谓分化程度只是透视滤镜，不是绝对层级 |

**工程启示：** 自进化系统的细胞身份不应是硬编码的"不可逆路径"，而应是**状态空间中的可迁移节点**。传统编程中一旦L0分化为L1就无法回头，但宇宙第4公理告诉我们——没有不可逆，只有"还没找到反向路径"。

**实现方案——可逆分化标识：**

```python
@dataclass
class CellIdentity:
    """细胞身份——支持可逆分化、转分化的弹性身份系统"""
    cell_type: str
    lineage_path: List[str]  # 分化路径记录（可回溯）
    plasticity: float        # 可塑性系数 0.0~1.0（1.0=全能，0.0=终末）
    
    def dedifferentiate(self):
        """去分化——沿lineage_path回溯一层"""
        if len(self.lineage_path) > 1:
            self.lineage_path.pop()
            self.cell_type = self.lineage_path[-1]
            self.plasticity = min(1.0, self.plasticity + 0.2)
            
    def transdifferentiate(self, target_type: str):
        """转分化——直接切换为另一分化路径的细胞"""
        if self.plasticity < 0.5:
            raise InsufficientPlasticityError("需要先去分化提高可塑性")
        self.cell_type = target_type
        self.lineage_path.append(target_type)
```

### 公理5：躯体代谢循环 → 细胞代谢与身份耦合

干细胞代谢模式直接决定它的"身份"。这是宇宙第5公理的直接工程复刻：

| 代谢模式 | 宇宙对应 | 细胞状态 | 分化潜能 |
|:---|:---|:---:|:---:|
| 糖酵解（低耗氧） | 星云稀薄扩散态（未凝聚） | 干细胞/未分化 | 高 |
| 糖酵解+氧化磷酸化混合 | 星云局部凝聚过程 | 祖细胞 | 中 |
| 氧化磷酸化为主（高耗氧） | 恒星稳态燃烧（凝聚态） | 终末分化功能细胞 | 低 |
| 代谢衰竭 | 恒星耗尽/黑洞分解 | 细胞凋亡 | 无 |

**核心规律：低代谢 = 高分化潜能，高代谢 = 功能专一化。**

**工程启示：** 通过调控细胞的代谢模式（而非信号因子），来驱动或抑制分化。代谢开关是比信号因子更可控、更内源的分化调控手段。

**实现方案——代谢开关驱动分化：**

```python
class MetabolicSwitch:
    """代谢开关——通过调控代谢模式驱动分化"""
    
    def __init__(self):
        self.glycolysis_rate = 0.8   # 糖酵解占比
        self.oxphos_rate = 0.2       # 氧化磷酸化占比
        
    def promote_differentiation(self):
        """增加氧化磷酸化，驱动分化"""
        self.oxphos_rate = min(0.9, self.oxphos_rate + 0.1)
        self.glycolysis_rate = 1.0 - self.oxphos_rate
        
    def promote_self_renewal(self):
        """增加糖酵解，维持干细胞态"""
        self.glycolysis_rate = min(0.9, self.glycolysis_rate + 0.1)
        self.oxphos_rate = 1.0 - self.glycolysis_rate
    
    def cell_fate_from_metabolism(self) -> str:
        """根据代谢模式决定细胞命运"""
        if self.glycolysis_rate > 0.7:
            return "self_renew"   # 糖酵解为主→保持干细胞
        elif self.oxphos_rate > 0.7:
            return "differentiate"  # 氧化磷酸化为主→分化
        else:
            return "transitional"   # 混合→过渡态
```

## 公理1：一体同源 → 全息溯源链

### 宇宙态

万物同源，每个局部包含全域全部信息。人体细胞的DNA保存了构建整个人的蓝图。

### 系统现有态

干细胞池是源头，分化后子细胞功能特化。但分化后的子细胞**不保留与干细胞的连接路径**——它知道自己是什么，但不知道自己从哪来。

### 裂隙

分化后的L1细胞与源头L0干细胞的「亲缘关系」不持久化。当某区域需要修复时，无法快速回溯到正确的干细胞源头。

### 完善方向：全息溯源链

在每个分化的L1细胞中嵌入一条轻量级溯源链：

```python
@dataclass
class LineageTrace:
    cell_id: str              # 本细胞唯一ID
    stem_cell_id: str         # 源头干细胞ID
    differentiation_path: List[str]  # 分化路径 ["L0_肝祖", "L1_肝细胞"]
    generation: int           # 分化代数（生数→成数标记）
    genome_version: str       # 分化时的基因组版本快照
```

**工程规则：**
- 每个L1细胞在分化时**继承**其L0干细胞的基因链引用，同时记录自身的分化路径。
- 当修复信号触发时，局部细胞通过溯源链快速定位对应的干细胞类型，而非全局搜索。
- 溯源链只读、不可篡改，写入一次后随细胞生命周期结束自动销毁。

### 河图数理对应

河图生数1-5为潜能层（L0），成数6-10为功能层（L1）。**成数不是独立的——它=生数+5。** 同理，分化的L1细胞应天然携带其L0干细胞的「生数标记」，任何时候都能反查源头。

## 公理2：核心自转统摄 → 旋动统摄脉冲

### 宇宙态

每个结构有核心，核心高速自转产生统摄力，收拢周边物质、维持结构有序（如银河系核束缚亿万恒星在旋臂中运行）。

### 系统现有态

干细胞巢（niche）通过信号通路定向分化，但分化是「线性指令式」——指令发出去、细胞执行，缺少一股持续的力来维持分化区域的**空间秩序**。

### 裂隙

分化出来的细胞容易无序扩散，没有自组织的结构稳定。没有「旋动约束」来让细胞在空间中形成有序排列。

### 完善方向：旋动统摄脉冲

干细胞巢除释放分化信号外，同时发出周期性的**统摄脉冲**（类似心跳），约束周边分化的子细胞以巢为中心形成空间有序的排列：

```python
class StemCellNiche:
    # 每个干细胞巢维护一个统摄脉冲发生器
    pulse_frequency: float = 1.0  # Hz，脉冲频率决定分化细胞的空间密度
    pulse_strength: float        # 脉冲强度决定约束半径
    
    def emit_pulse(self):
        # 周期性广播一个"统摄信号"
        # 周边所有L1细胞收到后自动调整自身相对于巢的位置
        pass
    
    def differentiate(self, target_type):
        # 分化前先锁频——让子细胞对齐当前的脉冲节律
        daughter = self.stem_cell.differentiate(target_type)
        daughter.sync_pulse(self.current_frequency)
        return daughter
```

**工程规则：**
- 巢的脉冲频率决定分化细胞的空间密度（频率越高→细胞越密集）。
- 脉冲强度决定约束半径（强度越大→约束范围越广）。
- 当巢脉冲停止（巢死亡或休眠），周边分化的细胞自动进入游离态。
- 脉冲不传递业务数据，只传递位置约束——保持信号纯净。

**宇宙类比：** 星系核不自转时，星系会解体。干细胞巢的统摄脉冲就是系统层面的「微型星系核自转」。

## 公理3：尺度相对同构 → 分形自相似分化约束

### 宇宙态

原子核→细胞→器官→人体→星系，共享同一套结构规则。大尺度和小尺度是同构的，只是介质密度不同。

### 系统现有态

分化树（过程）和目标组织结构（结果）之间**没有同构约束**。分化是1→N的树状过程，成品结构可能是管状、球状、网状——两者拓扑不匹配。

### 裂隙

一个树状分化过程，如何生成一个非树状的3D结构？缺少「分化路径与目标组织的拓扑同构约束」。

### 完善方向：分形自相似分化约束

设计分化路径与目标组织的拓扑同构——分化过程本身就是目标结构的**自相似缩微**：

```python
# 分化规则的拓扑约束模板
TISSUE_TOPOLOGY = {
    "tubular": {        # 管状结构（血管/气管）
        "mode": "branching",        # 主干+分支式分化
        "fractal_depth": 3,         # 分形深度
        "branch_angle": 45,         # 分支角度（度）
        "self_similar": True,       # 每次分叉复刻上一级拓扑
    },
    "spherical": {      # 球状结构（器官囊泡）
        "mode": "radial",           # 核心→皮层径向分化
        "shell_count": 4,           # 皮层壳层数
        "radial_symmetry": True,    # 径向对称
    },
    "network": {        # 网状结构（神经网络）
        "mode": "mesh",            # 网格式分化
        "node_degree": 3,           # 每个节点连接数
        "lattice_type": "hexagonal", # 六角网格
    },
}
```

**工程规则：**
- L-1基因组中预设每个目标组织的拓扑模板。
- L0干细胞分化时，读取目标组织的拓扑约束，自动约束分化路径的空间排布。
- 分化过程不产生"自由细胞"，每一次分裂的位置和方向都由拓扑模板决定。
- 分形深度耗尽时，分化自然停止——不产生多余细胞。

**宇宙类比：** 银河系旋臂的形态和星系内部旋涡星云的形态同构——大旋臂套小旋臂，由自转统摄力自然形成，不是拼出来的。

## 公理4：时空镜像透视 → 内部全息状态图

### 宇宙态

深空观测看到的不是百亿年前的遗迹，而是当下宇宙本体的全息镜像。每个局部都携带全域的信息。

### 系统现有态

系统监测依赖外部日志和传感器——人在看日志、人在调参。系统**没有内建的全息自监测能力**，不知道自己长什么样。

### 裂隙

系统没有一个「内部的自我镜像」——它不知道自己在做什么，只有外部观察者在知道。

### 完善方向：分布式全息状态图

在每个关键节点（干细胞巢/正在分化的细胞群/已形成的组织）维护一个轻量级全息状态摘要：

```python
@dataclass
class HolographicState:
    node_id: str                       # 当前节点ID
    node_type: str                     # 节点类型（巢/分化群/组织）
    local_state: dict                  # 自身状态摘要
    neighbor_states: Dict[str, dict]   # 相邻节点的状态摘要（不完整，但够用）
    global_health_estimate: float      # 对全局健康度的本地估算（0.0-1.0）
    last_pulse_sync: float             # 上次统摄脉冲同步时间
```

**工程规则：**
- 每个节点不维护完整全局数据，只维护「自身+邻居」的局部全息摘要。
- 统摄脉冲携带全局健康度的压缩编码（单一float值），节点收到后更新自身估算。
- 局部全息图不替代中央监控，但让系统在中央监控失效时仍有分布式自感知能力。
- 新的全息数据**覆盖**旧数据，不堆叠——保持摘要轻量。

**宇宙类比：** 身体每个细胞都有完整DNA，但只表达自己需要的那部分。全息信息存在，局部化表达，两者不矛盾。

## 公理5：躯体代谢循环 → 细胞代谢回收闭环

### 宇宙态

黑洞回收衰老恒星→喷流输出纯净基础粒子→再形成新恒星。物质永不浪费，只是形态转化。

### 系统现有态

细胞分化后功能完成、衰减、死亡，可能有凋亡机制，但**死亡的细胞产物没有被系统回收利用**——资源单向消耗。

### 裂隙

死亡的L1细胞、错误分化的废弃细胞、完成使命的组织碎片——它们占用的资源没有被回收。系统越跑资源越少。

### 完善方向：细胞代谢回收闭环

建立「标记→拆解→再分配」三级回收流水线：

```python
class CellMetabolismRecycler:
    # 回收站——每个L2脏腑组织配一个
    
    def mark_apoptosis(self, cell_id: str, reason: str):
        """① 标记：到期/错误/指令凋亡的细胞进入回收态"""
        pass
    
    def disassemble(self, cell_id: str) -> List[MolecularModule]:
        """② 拆解：将回收态细胞拆解为基础分子模块"""
        # 拆解产物：蛋白质片段、ATP残余、脂质、核酸片段
        return [
            MolecularModule(type="protein", amount=0.3, quality=0.8),
            MolecularModule(type="atp_residue", amount=0.1),
            MolecularModule(type="lipid", amount=0.2),
        ]
    
    def redistribute(self, modules: List[MolecularModule], target_stem_cell_pool: str):
        """③ 再分配：基础模块返回干细胞池的营养库"""
        pass
```

**工程规则：**
- 拆解产物按类型分类归入干细胞池的「营养库」，不直接丢回。
- 营养库的存量影响分化阈值——营养充足时分化成本降低。
- 不能回收的信号/无法拆解的毒素→归入代谢废物，走排泄通道，不循环。
- 回收有转化损耗（如蛋白质片段仅70%可复用），留存30%作为代谢熵，保证系统不会无限堆积。

**宇宙类比：** 黑洞不浪费任何物质，只是改变形态。系统也不应浪费任何一个细胞——它只是从功能态变回原料态。

## 跨层整合：河图数理分化控制总线

五条公理各自产生一个完善方向，但它们需要一条**统一的分化控制总线**来协调。这条总线就是河图数理。

### 生数→成数的分化定轨

```
L0 干细胞池 = 河图生数层（1-5，具全部潜能）
         │
         ├─ 生数1（水 · 肾类）→ 分化 +5 = 成数6
         ├─ 生数2（火 · 心类）→ 分化 +5 = 成数7
         ├─ 生数3（木 · 肝类）→ 分化 +5 = 成数8
         ├─ 生数4（金 · 肺类）→ 分化 +5 = 成数9
         └─ 生数5（土 · 脾类）→ 分化 +5 = 成数10
```

### 五个完善方向在数理中的定位

| 完善方向 | 主导数理 | 作用层级 | 控制信号 |
|:---|:---:|:---:|:---|
| 全息溯源链 | 河图生+5=成 | L0→L1 | 溯源标记（只读） |
| 旋动统摄脉冲 | 洛书九宫离心力 | L1 | 脉冲频率/强度 |
| 分形自相似约束 | 河图成数回退生数 | L1→结构 | 拓扑模板匹配 |
| 分布式全息状态图 | 洛书对宫和10 | L1-L2-L3 | 压缩健康度浮点 |
| 代谢回收闭环 | 五行相生闭圈 | L1→L0 | 营养库存量阈值 |

### 数理约束的非线性特征

**与传统线性系统的关键区别：** 这套框架中的所有约束条件是**对偶的**——一个参数同时影响两个方向：

- 统摄脉冲频率 ↑ → 分化密度 ↑ → 拆解回收率 ↑（代谢加速）
- 统摄脉冲频率 ↓ → 分化密度 ↓ → 拆解回收率 ↓（代谢减慢）

同一个旋钮同时控制「生成」和「回收」——这就是河图数理的对偶性在工程中的体现。没有独立的新陈代谢旋钮和分化旋钮，同一套数理在控制两者。

### 8.1 一体同源 → SystemOntology 本体定义层

#### 设计目标

现有全息溯源链解决的是「从哪来」的追踪问题，但没有回答「为什么存在」的存在论问题。
本体定义层为全系统提供不可变的「存在目的宣言」——所有分化行为必须以此为约束。

#### 核心数据结构

```python
from dataclasses import dataclass, field
from enum import IntEnum
from typing import Final, List

class Goal(IntEnum):
    METABOLIC_STABILITY = 0  # 代谢稳定 → 第一优先级
```

### 8.2 核心自转统摄 → CoreNucleus 统摄核

#### 设计目标

现有「旋动统摄脉冲」由干细胞巢发出，作用是空间约束。但宇宙的「核心自转」比这更根本——**它是整个系统的引力源，所有子系统围绕它做周期运动。** 
统摄核是一个持续的、全系统范围的引力场发生器——不只是干细胞巢的信号。

#### 核心数据结构

```python
from dataclasses import dataclass, field
from threading import Event, Thread
import time
import math
from typing import Callable

@dataclass
class SatelliteOrbit:
    """绕核运行的卫星（任何子系统）轨道参数"""
    satellite_id: str
    # 当前相位角（0-360度），表示在该周期中的位置
    phase: float = 0.0
    # 轨道半径（离核心的"距离"——可以是逻辑距离/层级深度）
    radius: float = 1.0
    # 自转速度倍率（相对核心基频）
    speed_multiplier: float = 1.0
    # 最近一次同步时间戳
    last_sync: float = 0.0
    # 该卫星是否在线
    is_alive: bool = True

class CoreNucleus:
    """
    系统的「引力核心」——持续自转，所有子系统围绕它运转。
    
    相当于宇宙中的银心/原子核。不自转就没有结构稳定。
    它不是管理者，是引力源。
    """
    
    def __init__(self, base_frequency_hz: float = 0.033):  # 约每30秒一圈
        self.base_frequency = base_frequency_hz
        self.satellites: dict[str, SatelliteOrbit] = {}
        self._running = False
        self._thread: Thread | None = None
        self._stop_event = Event()
        # 当前自转圈数（宇宙年龄）
        self.rotation_count: int = 0
        # 每次自转时的回调列表
        self.on_tick_callbacks: list[Callable] = []
    
    def start(self):
        """启动核心自转"""
        self._running = True
        self._thread = Thread(target=self._rotate, daemon=True, name="CoreNucleus")
        self._thread.start()
    
    def _rotate(self):
        """自转主循环"""
        period = 1.0 / self.base_frequency
        while not self._stop_event.is_set():
            tick_start = time.monotonic()
            self.rotation_count += 1
            
            # 更新所有卫星的相位
            for sat in self.satellites.values():
                if sat.is_alive:
                    sat.phase = (sat.phase + 360.0 * sat.speed_multiplier / 
                                 (period * self.base_frequency)) % 360.0
                    sat.last_sync = tick_start
            
            # 执行自转回调
            for cb in self.on_tick_callbacks:
                try:
                    cb(self.rotation_count, dict(self.satellites))
                except Exception:
                    pass  # 回调不阻塞核心自转
            
            # 等待到下一个周期
            elapsed = time.monotonic() - tick_start
            time.sleep(max(0, period - elapsed))
    
    def register_satellite(self, sat_id: str, radius: float = 1.0) -> SatelliteOrbit:
        """注册一个新的卫星（子系统）"""
        orbit = SatelliteOrbit(
            satellite_id=sat_id,
            radius=radius,
            last_sync=time.monotonic(),
        )
        self.satellites[sat_id] = orbit
        return orbit
    
    def check_cohesion(self) -> dict[str, float]:
        """
        检查系统凝聚力——所有卫星与核心的同步偏差。
        
        返回每个卫星的"同步偏差度"（0.0=完全同步，1.0=完全失步）。
        偏差超过阈值 → 触发失衡预警。
        """
        now = time.monotonic()
        cohesion: dict[str, float] = {}
        period = 1.0 / self.base_frequency
        
        for sat_id, sat in self.satellites.items():
            if not sat.is_alive:
                cohesion[sat_id] = 1.0  # 失联即完全失步
                continue
            time_since_sync = now - sat.last_sync
            # 超过3个周期未同步 → 视为失步
            deviation = min(1.0, time_since_sync / (period * 3))
            cohesion[sat_id] = deviation
        
        return cohesion
    
    def stop(self):
        """停止核心自转"""
        self._stop_event.set()
        if self._thread:
            self._thread.join(timeout=5)
        self._running = False
```

#### 与现有系统的对接

| 对接点 | 方式 |
|:---|:---|
| L0 干细胞池 | 每个L0注册为一个卫星，按"分化类型"分配轨道半径 |
| L1 分化细胞群 | 每个分化群注册为一个卫星组，共享轨道半径 |
| L3 四大中枢 | 每个中枢（免疫/内分泌/神经/皮层）注册为独立卫星 |
| 统摄脉冲 | 核心的自转节律就是之前「旋动统摄脉冲」的源头 |
| 失衡检测 | `check_cohesion()` 的输出直接喂给因果引擎的九宫检测 |
| 生命周期 | 系统启动时 start()，关闭时 stop() |

### 8.3 尺度相对同构 → SelfSimilarConstraint 自相似约束

#### 设计目标

现有「分形自相似分化约束」聚焦于分化路径与目标组织的拓扑同构。
但宇宙的尺度同构更深刻——**每一层内部的结构与整体同构**。
一个L0干细胞的内部结构，应该和L3完整系统的结构类似（只是规模不同）。

#### 核心数据结构

```python
from dataclasses import dataclass, field
from typing import Any, Protocol

class LayerStructure(Protocol):
    """每一层必须实现的结构接口"""
    def get_internal_structure(self) -> dict[str, Any]: ...
    def get_self_state(self) -> dict[str, float]: ...

@dataclass
class SelfSimilarConstraint:
    """
    自相似结构约束——校验每一层的内部拓扑是否与整体同构。
    """
    
    # 每一层必须包含的"核心要素"
    REQUIRED_ELEMENTS: tuple[str, ...] = (
        "core_nucleus",     # 核心自转（公理2）
        "metabolic_cycle",  # 代谢循环（公理5）
        "holographic_view", # 全息感知（公理4）
    )
    
    @staticmethod
    def verify(layer: LayerStructure, level: int) -> dict[str, bool]:
        """
        校验该层的内部结构是否满足自相似约束。
        
        Args:
            layer: 要校验的层实例
            level: 层级编号（-1=基因组, 0=干细胞, 1=体细胞, 2=组织, 3=生物体）
        
        Returns:
            每个要素的校验结果字典
        """
        structure = layer.get_internal_structure()
        results = {}
        
        for elem in SelfSimilarConstraint.REQUIRED_ELEMENTS:
            has_element = elem in structure
            is_properly_nested = False
            
            if has_element:
                # 校验该要素的内部结构是否也满足自相似
                inner = structure[elem]
                if hasattr(inner, 'get_internal_structure'):
                    inner_results = SelfSimilarConstraint.verify(inner, level + 1)
                    is_properly_nested = all(inner_results.values())
                else:
                    is_properly_nested = True  # 最底层，不能再递归
            
            results[elem] = has_element and is_properly_nested
        
        return results
    
    @staticmethod
    def get_recursive_depth(layer: LayerStructure, max_depth: int = 10) -> int:
        """
        获取该层的递归深度——递归越深，结构越接近全息同构。
        """
        depth = 0
        current = layer
        for _ in range(max_depth):
            structure = current.get_internal_structure()
            if 'core_nucleus' in structure and hasattr(structure['core_nucleus'], 'get_internal_structure'):
                current = structure['core_nucleus']
                depth += 1
            else:
                break
        return depth
```

|:---|:---|
| L0-L3所有层 | 每层实现 `get_internal_structure()` 接口 |

### 8.4 时空镜像透视 → HolographicMirror 全息镜像

#### 设计目标

现有「分布式全息状态图」让节点维护自身+邻居的局部状态摘要。
但宇宙的「时空镜像」比这更进一层——**每个局部都携带整个系统的全息信息**。
对应到工程：每个L1细胞不是只知道自己和邻居，而是持有一个「整个系统的压缩快照」。
诊断方式从「链路追踪」变为「相干检测」——看一个细胞就知道整个系统是否健康。

#### 核心数据结构

```python
from dataclasses import dataclass, field
from typing import Any
import struct

@dataclass
class GlobalStateSnapshot:
    """全局状态的压缩快照（轻量级，不可用于精确分析，只用于相干检测）"""
    # 全局健康度（平均）
    global_health: float = 1.0
    # 九宫失衡度
    nine_palace_imbalance: float = 0.0
    # 活跃细胞总数
    total_cells: int = 0
    # ATP池利用率
    atp_utilization: float = 0.0
    # 分化速率（单位时间）
    differentiation_rate: float = 0.0
    # 凋亡/回收速率
    recycling_rate: float = 0.0
    # 全局心跳相位
    heartbeat_phase: float = 0.0
    
    @classmethod
    def from_compressed(cls, data: bytes) -> 'GlobalStateSnapshot':
        """从压缩字节重建（7个float = 56字节）"""
        vals = struct.unpack('!7f', data)
        return cls(*vals)
    
    def to_compressed(self) -> bytes:
        """压缩为56字节"""
        return struct.pack('!7f',
            self.global_health,
            self.nine_palace_imbalance,
            self.total_cells,
            self.atp_utilization,
            self.differentiation_rate,
            self.recycling_rate,
            self.heartbeat_phase,
        )

@dataclass
class HolographicMirror:
    """
    每个L1细胞携带的「全息镜像」。
    通过它，看一个细胞就能感知整个系统的健康状态。
    """
    cell_id: str
    cell_type: str
    
    # ① 自身局部状态
    local_state: dict[str, float] = field(default_factory=dict)
    
    # ② 全局快照（全息压缩）
    global_snapshot: GlobalStateSnapshot = field(default_factory=GlobalStateSnapshot)
    
    # ③ 相干度——局部与全局的偏差度
    # 0.0 = 完全背离全局, 1.0 = 完全同步
    # 某个细胞的相干度突然下降 → 它可能是病灶
    coherence: float = 1.0
    
    def compute_coherence(self) -> float:
        """
        计算本细胞与全局的相干度。
        
        原理：宇宙的每个局部都包含全域信息——如果局部严重偏离全域，
        说明这个局部可能出了问题。
        """
        if not self.local_state:
            return 1.0
        
        # 使用局部健康度与全局健康度的比值作为相干度
        local_health = self.local_state.get('health', 1.0)
        global_health = self.global_snapshot.global_health
        
        if global_health == 0:
            return 0.0
        
        # 相干度 = 1 - |局部-全局|/max(局部,全局)
        deviation = abs(local_health - global_health) / max(local_health, global_health, 0.1)
        self.coherence = max(0.0, min(1.0, 1.0 - deviation))
        return self.coherence

class CoherenceDiagnosis:
    """基于全息镜像的分布式诊断器"""
    
    @staticmethod
    def find_anomalies(mirrors: list[HolographicMirror], 
                       threshold: float = 0.3) -> list[dict]:
        """
        找出相干度过低的异常细胞。
        
        替代传统的链路追踪——不需要从L3一层层追到L1，
        直接扫描所有细胞的相干度，低的就是病灶候选。
        """
        anomalies = []
        for m in mirrors:
            coh = m.compute_coherence()
            if coh < threshold:
                anomalies.append({
                    'cell_id': m.cell_id,
                    'cell_type': m.cell_type,
                    'coherence': coh,
                    'local_health': m.local_state.get('health', 0),
                    'global_health': m.global_snapshot.global_health,
                })
        return sorted(anomalies, key=lambda x: x['coherence'])
```

|:---|:---|
| L1 每个体细胞 | 创建时附带一个HolographicMirror实例 |
| 统摄脉冲 | 脉冲中携带GlobalStateSnapshot的压缩字节（56字节） |
| 中央监控 | CoherenceDiagnosis替代部分日志排查 |
| 因果引擎 | 异常细胞列表直接喂给因果引擎做根因分析 |

### 8.5 躯体代谢循环 → MetabolicRecycler 代谢回收器

#### 设计目标

现有「细胞代谢回收闭环」提出了基本的回收概念。
但宇宙的「躯体代谢循环」是**完全闭环的**——没有物质会离开系统。
黑洞降解衰老物质，喷流输送基础粒子，再生新恒星。
对应到工程：每个L1细胞凋亡时，它的经验、代码模式、数据以「基础粒子」的形式被回收，
供给下一代细胞使用。

#### 核心数据结构

```python
from dataclasses import dataclass, field
from typing import Any
import hashlib
import json
from enum import Enum, auto
import time

class ParticleType(Enum):
    EXPERIENCE = auto()      # 经验模式（抽象化的决策经验）
    CODE_PATTERN = auto()    # 代码模式（可复用的实现模板）
    ANONYMIZED_DATA = auto() # 匿名化数据
    ATP_CREDIT = auto()      # ATP能量积分

@dataclass
class BaseParticle:
    """
    基础粒子——代谢回收的最小单元。
    相当于黑洞降解后的「纯净基础粒子」。
    """
    particle_id: str
    type: ParticleType
    value: Any  # 不同类型的值不同
    quality: float  # 质量评分（0.0-1.0）
    source_cell_type: str  # 来源细胞类型
    created_at: float = field(default_factory=time.time)
    
    def hash(self) -> str:
        """去重哈希"""
        raw = f"{self.type.value}:{json.dumps(self.value, sort_keys=True, default=str)}"
        return hashlib.sha256(raw.encode()).hexdigest()[:16]

@dataclass
class ResourcePool:
    """
    资源池——存储所有已回收的「基础粒子」。
    相当于星系之间的星际介质（ISMedium）——从回收口聚集的粒子待用。
    """
    # 按类型分池
    pools: dict[ParticleType, list[BaseParticle]] = field(default_factory=dict)
    # 当前总容量
    total_particles: int = 0
    # 最大容量（超过时会驱逐低质量粒子）
    max_capacity: int = 10000
    
    def add(self, particle: BaseParticle):
        """存入一个基础粒子"""
        if particle.type not in self.pools:
            self.pools[particle.type] = []
        
        pool = self.pools[particle.type]
        # 去重
        h = particle.hash()
        if any(p.hash() == h for p in pool):
            return  # 重复粒子，丢弃
        
        pool.append(particle)
        self.total_particles += 1
        
        # 超容量时驱逐低质量粒子
        if self.total_particles > self.max_capacity:
            self._evict_lowest_quality()
    
    def _evict_lowest_quality(self):
        """驱逐所有池中质量最低的10%"""
        all_particles = []
        for pool in self.pools.values():
            all_particles.extend(pool)
        all_particles.sort(key=lambda p: p.quality)
        evict_count = max(1, len(all_particles) // 10)
        evicted = set(id(p) for p in all_particles[:evict_count])
        
        for ptype in list(self.pools.keys()):
            self.pools[ptype] = [p for p in self.pools[ptype] if id(p) not in evicted]
        
        self.total_particles = sum(len(p) for p in self.pools.values())
    
    def draw(self, ptype: ParticleType, count: int = 1, 
             min_quality: float = 0.0) -> list[BaseParticle]:
        """
        从池中提取基础粒子（用于构建新细胞）。
        优先给出最优质的粒子。
        """
        pool = self.pools.get(ptype, [])
        candidates = [p for p in pool if p.quality >= min_quality]
        candidates.sort(key=lambda p: p.quality, reverse=True)
        
        taken = candidates[:count]
        for p in taken:
            pool.remove(p)
        
        self.total_particles = sum(len(p) for p in self.pools.values())
        return taken

class MetabolicRecycler:
    """
    代谢回收器——系统的「黑洞」。
    接收凋亡的L1细胞，执行物质回收。
    不丢弃任何东西 → 降解 → 分流 → 再生。
    """
    
    def __init__(self):
        self.resource_pool = ResourcePool()
        # 回收统计
        self.total_recycled: int = 0
        self.total_regenerated: int = 0
    
    def degrade(self, cell: Any) -> list[BaseParticle]:
        """
        降解一个细胞为基础粒子。
        
        类似于黑洞将衰老恒星拆解为基础粒子。
        """
        particles = []
        
        # ① 提取经验模式（如果有）
        if hasattr(cell, 'get_experience'):
            exp = cell.get_experience()
            if exp:
                particles.append(BaseParticle(
                    particle_id=f"exp_{time.time_ns()}",
                    type=ParticleType.EXPERIENCE,
                    value=exp,
                    quality=getattr(cell, 'performance', 0.5),
                    source_cell_type=type(cell).__name__,
                ))
        
        # ② 提取代码模式（如果有）
        if hasattr(cell, 'get_code_pattern'):
            pattern = cell.get_code_pattern()
            if pattern:
                particles.append(BaseParticle(
                    particle_id=f"pat_{time.time_ns()}",
                    type=ParticleType.CODE_PATTERN,
                    value=pattern,
                    quality=0.7,
                    source_cell_type=type(cell).__name__,
                ))
        
        # ③ 回收ATP积分
        atp_credit = getattr(cell, 'atp_credit', 0.0)
        if atp_credit > 0:
            particles.append(BaseParticle(
                particle_id=f"atp_{time.time_ns()}",
                type=ParticleType.ATP_CREDIT,
                value=atp_credit,
                quality=1.0,
                source_cell_type=type(cell).__name__,
            ))
        
        # 存入资源池
        for p in particles:
            self.resource_pool.add(p)
        
        self.total_recycled += 1
        return particles
    
    def regenerate(self, cell_type: str, demand: str = '') -> dict[str, Any]:
        """
        从基础粒子中「再生」——为新细胞组装初始状态。
        
        相当于黑洞喷流携带基础粒子输送到贫瘠空域，催生新恒星。
        """
        seed: dict[str, Any] = {
            'type': cell_type,
            'experience': None,
            'code_pattern': None,
            'atp_credit': 0.0,
        }
        
        # 从池中提取最合适的经验
        exp_particles = self.resource_pool.draw(ParticleType.EXPERIENCE, count=1, min_quality=0.3)
        if exp_particles:
            seed['experience'] = exp_particles[0].value
        
        # 从池中提取最合适的代码模式
        pat_particles = self.resource_pool.draw(ParticleType.CODE_PATTERN, count=1, min_quality=0.5)
        if pat_particles:
            seed['code_pattern'] = pat_particles[0].value
        
        # 从池中提取ATP积分
        atp_particles = self.resource_pool.draw(ParticleType.ATP_CREDIT, count=1)
        if atp_particles:
            seed['atp_credit'] = atp_particles[0].value
        
        self.total_regenerated += 1
        return seed
    
    def get_cycle_efficiency(self) -> float:
        """代谢循环效率 = 再生数 / 回收数（理想值≈1.0）"""
        if self.total_recycled == 0:
            return 0.0
        return min(1.0, self.total_regenerated / self.total_recycled)
```

| 对接点 | 方式 |
|:---|:---|
| L1 细胞销毁 | 销毁前调用 `recycler.degrade(cell)` 回收资源 |
| L0 干细胞分化 | 分化时调用 `recycler.regenerate(type)` 获取初始资源 |
| L3 全局监控 | `get_cycle_efficiency()` 作为系统健康指标之一 |
| ATP管理 | 回收的ATP积分直接归还ATP池 |

### 8.6 五者联动——完整的因果闭环

五个方向不是孤立的，它们构成一个完整的**因果闭环**：

```
 SystemOntology（本体定义 → 存在的意义）
        │
        ▼
 CoreNucleus（统摄核 → 引力场 / 节奏源）
    ┌───┼───┬───┬───┐
    ▼   ▼   ▼   ▼   ▼
 自相似  全息镜像  代谢回收
 (结构)  (诊断)   (物质)
    │       │       │
    └───┬───┴───┬───┘
        ▼       ▼
    结构稳定  物质闭环
        │       │
        └───┬───┘
            ▼
     SystemOntology
   (反馈：系统更稳定→本体更清晰)
```

**每一层的输出都是下一层的输入：**

| 输入 | 源于 | 作用于 |
|:---|:---|:---|
| 存在优先级 | SystemOntology | CoreNucleus的注册规则 |
| 统摄频率 | CoreNucleus | 自相似约束的校验周期 |
| 拓扑模板 | SelfSimilarConstraint | 全息镜像的数据结构 |
| 相干度异常 | HolographicMirror | 代谢回收器的触发信号 |
| 回收效率 | MetabolicRecycler | 新细胞的能力（含经验） |

**系统启动顺序：**
```
1. SystemOntology 加载（读identity）
2. CoreNucleus 启动自转（引力场建立）
3. SelfSimilarConstraint 注册校验器
4. HolographicMirror 开始在脉冲中传播
5. MetabolicRecycler 初始化资源池
6. L0干细胞开始分化（遵循全部五层约束）
```

## 阶段四 🌱 — 自进化闭环（第7-8周）

**目标**：演化引擎成为系统迭代的驱动力。

### 核心安全策略
> **版本化石机制**：演化结果不直接覆盖 genome.json，而是创建新版本号 + 原子切换软链接。

### 任务清单

#### 4.1 — 演化触发点定义
- [ ] **定时触发**：每日凌晨自动跑一轮演化（默认为空跑）
- [ ] **异常触发**：某 Agent 连续失败率 > 5% → 自动触发该 Agent 的变异搜索
- [ ] **手动触发**：`bridge.evolve(genome_path, target_contract="CodeAssistant")`

#### 4.2 — 演化结果自动采纳
- [ ] `EvolutionPipeline::run` 返回最优变体 → 写入 `data/candidates/` 暂存区
- [ ] 自动灰度验证（初期可人工审批）→ 合格后 `bionics_load_genome` 加载新基因组
- [ ] 旧版本自动归档为化石 `data/history/genome_v{N}.json`

#### 4.3 — 演化历史可视化
- [ ] `bridge.evolution_history(50)` → 生成迭代树
- [ ] 展示每次变异改了哪个契约、评分变化、是否被采纳

### 战术调整注入
> **L-1语义澄清**：「不可变」指运行时代码路径不可写入；基因组数据本身是**版本化序列**。演化 = 生成新版本 + 原子切换软链接，旧版本永不删除 ✓

## 附录：安全机制总规

### 三层熔断
| 层 | 触发条件 | 自动措施 |
|----|---------|---------|
| 调用层 | FFI 返回 -1 或 NULL | 重试 1 次 → fallback 旧实现 → 写告警日志 |
| 灰度层 | mirror 比对不一致 > 3 次 | 自动切回 old 模式 → 发送告警 |
| 系统层 | ATP 全部耗尽 / 细胞存活为 0 | 紧急降级：只读模式，禁止写操作 |

### 热回滚机制
- 每次 genome.json 更新前自动备份到 `data/history/genome_v{N}.json`
- 基因组版本号递增，旧版本永不删除
- 回滚命令：`bridge.rollback_genome(version=5)` — 30秒内回到上一稳定状态

### 演化红线（硬性约束）
| 红线 | 内容 | 违规后果 |
|------|------|---------|
| 分层红线 | 永不放开 L1 向 L-1 直接写权限 | 编译期拦截 + 运行时 panic |
| 数理红线 | 不永久改动 9 连接、五行配比、三三演化核心常量 | 代码审查拒绝 |
| 生命周期红线 | 所有细胞必须绑定 创建-心跳-凋亡 全链路 | 资源泄漏告警 |
| 演化红线 | 严格执行冷却周期，区分表观与种质修改 | 自动跳过本轮 |
