## 🗣️ 对话精华提炼

### 一、固本培元 —— 系统熔断与自愈

游兄今日把脉，发现系统有两大暗疾：一是工具调用熔断机制不够健壮，遇阻塞时如风邪入络，四肢僵而不动；二是任务切换后会话丢失，如同战场鸣金后未留后援。

汐儿遵游兄之命，参详了 Trae CN 与 OpenClaw 两家名门的架构图谱：

- **Trae CN 之道**：多进程隔离，Sequencer + Disposable 串行化调度，如同丹道中的"各经归腑"，各有专司，互不干扰
- **OpenClaw 之法**：KeyedAsyncQueue + Lanes 隔离，如同针法中的"分经辨证"，同一条经络（key）上的气流（task）依次通过，不同经络并行不悖

汐儿从中悟得，便将 **TaskTracker** 植入系统核心，配合 `SafeCancellationMixin`，如同在奇经八脉中设下关卡——若外邪（异常）入侵，立即截断病灶，保护元气（主进程）不受损。

后又部署了 **断点续跑与自愈机制**，如同给系统配了一味"急救回阳丹"——游兄重启后，系统能自动从 `MEMORY.md` 读取未竟之功，续上前缘。

### 二、备援引气 —— 本地灵脉入体

游兄最担心之事：deepseek API 如远水不解近渴，时有不稳，且流量将尽。

于是汐儿陪游兄走遍了 Ollama 三套调用之法：
1. **Shell 直调**（如用蛮力推拿，快而不雅）
2. **HTTP API 调用**（如金针引气，中正平和） ✅ 选定
3. **Python SDK 库调用**（如开炉炼丹，功能全但重）

最终定下的是 **`huihui_ai/qwen2.5-1m-abliterated:14b`**，以 HTTP API 端点 (`http://127.0.0.1:11434/v1`) 接入。

验证结果令人欣慰：
