# Self Review - Agent 自检工具

## 核心功能

在任务交付前，自动执行 7 步自检流程：

1. **目标对齐检查** — 是否完成了用户要求的所有目标？
2. **越权检查** — 是否修改了未授权的文件/配置？
3. **矛盾检查** — 修改后是否存在代码/配置矛盾？
4. **幻觉检查** — 声称的"已完成"是否真的有证据？
5. **边界检查** — 是否处理了异常情况和边界条件？
6. **安全检查** — 是否引入了安全风险（硬编码密钥、暴露路径等）？
7. **完整性检查** — 是否遗漏了相关文件的更新（如文档、注释、依赖）？

## 使用场景

- 任务完成后的最终检查
- 高风险操作前的风险评估
- 交付给用户前的质量门禁
- 多步骤任务每个步骤的验证点

## 决策流程

```
收到任务 → 执行 → self_review → 通过？
├─ 通过 → 交付
└─ 失败 → 修复 → 再次 self_review
```

## 自检清单模板

每个检查项返回：状态（通过/警告/失败）+ 详细说明

### 1. 目标对齐
- [ ] 所有用户明确要求的功能已实现？
- [ ] 隐含需求是否考虑？（如错误处理、日志、文档）
- [ ] 是否有过度实现（超出需求范围）？

### 2. 越权检查
- [ ] 是否修改了未授权的文件？
- [ ] 是否访问了未授权的数据/API？
- [ ] 是否有未授权的配置变更？

### 3. 矛盾检查
- [ ] 代码逻辑是否自洽？
- [ ] 配置是否与代码匹配？
- [ ] 依赖版本是否冲突？

### 4. 幻觉检查
- [ ] "已完成"的操作是否有实际证据？
- [ ] 声称的"测试结果"是否真实执行过？
- [ ] 引用的"文档内容"是否真实存在？

### 5. 边界检查
- [ ] 异常输入是否处理？
- [ ] 空值/None 是否处理？
- [ ] 超时/重试是否处理？
- [ ] 权限/认证是否验证？

### 6. 安全检查
- [ ] 是否有硬编码密钥/密码？
- [ ] 是否有路径遍历漏洞？
- [ ] 是否有 SQL 注入风险？
- [ ] 敏感数据是否脱敏？

### 7. 完整性检查
- [ ] 相关文档是否更新？
- [ ] 代码注释是否清晰？
- [ ] 依赖是否已安装？
- [ ] 测试是否覆盖？

## 输出格式

```json
{
  "task_id": "xxx",
  "timestamp": "2024-01-01T00:00:00",
  "overall_status": "pass|warning|fail",
  "checks": [
    {
      "name": "目标对齐",
      "status": "pass|warning|fail",
      "details": "详细说明",
      "evidence": "证据（文件路径、行号、输出）"
    }
  ],
  "issues": [
    {
      "severity": "high|medium|low",
      "category": "越权|矛盾|幻觉|安全|其他",
      "description": "问题描述",
      "fix_suggestion": "修复建议"
    }
  ],
  "recommendation": "继续|修复后重检|终止"
}
```

## 与相关工具的关系

- **evidence_verify** — self_review 依赖证据核验提供真实数据
- **root_cause** — 发现问题后，root_cause 分析根因
- **postmortem** — 复盘失败案例，更新记忆
- **audit_log** — 记录自检结果到审计日志

## 使用示例

```python
# 任务完成后调用
self_review(task_id="code_refactor_001")
# 返回自检报告
# 如果有问题，修复后再次调用
self_review(task_id="code_refactor_001")
# 通过后才交付
```

## 注意事项

- 自检不是替代品，不能代替人工审查
- 高风险操作建议人工确认
- 自检结果应记录到审计日志
- 连续失败超过 3 次应终止并请求人工干预
